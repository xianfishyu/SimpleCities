# V4 历史字节、单笔超限与取消预算确认及准入

https://github.com/xianfishyu/SimpleCities/issues/1

## Suggested label

## Problem and outcome

#21 在当前 256 边上限下测得最大 64 笔批量改造历史约 2.90 MiB 边际托管存活空间、4.01 MiB 领域估算，最大单笔估算约 64.2 KiB。累计估算 8 MiB、单笔估算 256 KiB 和纯核心 token 取消 10 ms 是监测/压力实验建议，尚未获确认为生产准入规则；领域估算也不是稳定的真实堆上界。

本票在目标规模压力证据基础上确认预算及超限产品行为，再实现可解释、原子且可测试的历史准入。200 米档 9,680 边满铺已获用户确认，其余三档 10K；此计数决定不属于待确认信息，144 FPS 与 100–300 ms 目标也不改变。

## Information still required

- 累计历史预算和单笔预算采用哪个计量口径及数值：领域估算、经过校准的保留空间估算或其他可执行口径；8 MiB/256 KiB 目前仅为候选。
- 累计超限采用何种历史裁剪策略，以及单笔本身超限时采用提交前拒绝或其他明确行为；不能默认静默丢弃该笔历史同时提交有效编辑。
- 核心取消警戒线与 Godot Esc 全链路恢复预算分别如何验收；10 ms 仅为核心 token 候选值，不代表完整输入响应预算。

这些行为确认前可继续只读资源测量与候选方案比较，不把建议值写入生产拒绝门。

## Scope

在容量扩展后的合法数据集上覆盖代表性 64 笔历史，包括简单建造、局部格段切分改造、整边改造、批量删除/改造、密集路口及高链点折线。测量保留同一个当前快照时释放历史所得的边际托管空间，明确共享引用、管理集合及估算误差；工作集变化不作为历史独占内存。

取消区分 token 发出到 worker 退出、Esc 输入到 UI 恢复，以及未提交计划不再被引用的三个边界。GC 自然回收没有固定毫秒承诺，强制全代 GC 的实验成本不得误记为 Dispose 或取消延迟。

## Acceptance criteria

- [ ] 用目标规模及补充高链点/密集路口场景复验 64 笔历史与最重单笔，报告领域估算、边际托管存活字节、共享计数及测量限制；不直接外推 256 条直路结果。
- [ ] 在明确记录的产品决定中冻结累计/单笔预算、计量口径、累计超限裁剪及单笔超限行为；8 MiB/256 KiB/10 ms 若采用，附适用于最终规模的证据。
- [ ] 实施已确认的准入规则，边界值与超限值分别测试；拒绝的编辑不改变活动快照、历史游标或有效工具状态，成功编辑仍与对应历史原子发布。
- [ ] Undo/Redo 分支、重复编辑与历史裁剪按已确认策略保持一致；存档加载和新建地图后历史清空行为不回退。
- [ ] 多次取消和释放未提交计划后不残留持续持有的计划/历史引用；分别报告 worker 退出与 UI 恢复延迟并对照各自已确认预算，正确标记提前完成或提交竞态。
- [ ] 不为满足释放时间主动强制生产全代 GC；显示、输入、历史和存档正确性回归通过，预算文档与生产行为一致。

    道路 Windows Release 性能复验¶

    当前命令与验证边界（2026-10-21）¶

    以下命令从仓库根运行，已静态核对现用工程、脚本与参数；本轮没有执行构建、Godot、导出或性能采样。语义诊断、编辑器/DAP 与实际图形/发布验收按 canonical QA Skill执行；CLI 独立运行不替代真实编辑器门禁。

    入口 用途
    tests/SimpleCities.RoadCore.Tests/SimpleCities.RoadCore.Tests.csproj 纯核心模型、规划/提交、查询、历史与 codec
    tests/SimpleCities.Application.Tests/SimpleCities.Application.Tests.csproj 槽事务、联合加载、UI/输入/导出静态边界
    tests/godot/road_product_scene_runtime_contract.gd 正式 CityMap 的真实输入到可见结果
    tests/godot/command_center_runtime_contract.gd HUD/建造坞/响应式/生命周期
    tests/godot/pause_menu_runtime_contract.gd 暂停、绑定、异步存档和退出
    run-road-release.ps1 独立 Windows Release 采集与证据身份核验 
    dotnet test tests/SimpleCities.RoadCore.Tests/SimpleCities.RoadCore.Tests.csproj
dotnet test tests/SimpleCities.Application.Tests/SimpleCities.Application.Tests.csproj --filter "FullyQualifiedName~ConstructionDockContractTests|FullyQualifiedName~ConstructionCategoryDefinitionTests|FullyQualifiedName~PauseMenuContractTests|FullyQualifiedName~InputBindingManagerContractTests|FullyQualifiedName~GameHUDCompositionContractTests"

$godotExecutable = (Get-Command godot.exe -ErrorAction Stop).Source
# godot.exe 须为 Mono 版；不在 PATH 时，将上行替换为其实际路径赋值。
& $godotExecutable --path . --resolution 1600x900 --script res://tests/godot/road_product_scene_runtime_contract.gd

    后一个入口需要实际图形和绘制，不能加 headless 后把超时或无首绘当成完整可视验收。编辑器/DAP、独立 Vulkan 和 Release 分别记录。日志/输出如需落盘必须选择本轮新目录，不能覆盖旧运行。

    在仓库根目录用 PowerShell 7 和 Python 3.11 以上运行。Godot 参数指向 Mono 编辑器的 godot.exe，避免控制台包装进程在发布结束后仍持有管道。数据集使用已通过严格 Codec 的 #24 载荷；测量期间不要同时构建、运行其他基准或切走游戏窗口。

    原 .scratch/ 已整体归档并完全移出Git追踪，2026-10-12会话归档时复查目录已不存在；之后的QA输出仍由Git忽略。两份本地压缩包、引用索引和Git历史恢复索引统一存放在运行证据目录：完整快照保留全部本地文件，引用包保留正式文档引用的运行目录及校验依赖。下面的 #24 数据集通过 python Scripts/QA/scratch_archive.py extract --directory v4-24-20260930 取得；默认使用仓库内引用包，缺少对应包时读取历史Git blob并校验原始字节，指定 --source git 可强制验证历史路径。浅克隆缺少blob时需补齐历史或提供压缩包。恢复会补齐 .gdignore；还原文件不替代当前二进制身份与运行验证。

    python Scripts/QA/scratch_archive.py extract --directory v4-24-20260930
if ($LASTEXITCODE -ne 0) { throw '数据恢复失败，保留现状' }
$godotExecutable = (Get-Command godot.exe -ErrorAction Stop).Source
$runTag = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N')
$releaseOutput = ".scratch/road-release-$runTag"
if (Test-Path -LiteralPath $releaseOutput) { throw '必须使用新的输出目录' }

./Scripts/QA/run-road-release.ps1 `
  -Godot $godotExecutable `
  -Datasets .scratch/v4-24-20260930/datasets `
  -Output $releaseOutput `
  -Seconds 30 -Warmup 5 -Cycles 10 -IncludePolylines

    Output 必须不存在，防止覆盖旧结果。默认顺序运行25/50/100米10K规范道路边、200米9,680边满铺；IncludePolylines 追加独立320边折线补充场景。-Cells 25 -Seconds 2 -Warmup 1 -Cycles 1 适合先检查入口，短试跑不替代持续性能验收。

    遇到系统音频设备不可用时，可用 -AudioDriver Dummy 明确进行无音频的图形对照，前后版本必须使用相同选项；选择会写入run-plan和实际进程参数。默认仍使用正常音频驱动，不会自动忽略初始化错误。无音频结果须单独标明，不能冒充完整音频环境的验收。

    专用 Windows Desktop Road Performance 预设通过 road_performance 特性选择 RoadTargetPerformance 主循环和正式 CityMap 主场景，保留自动加载及正常存档准入。它不依赖可能被导出模板禁用的 --script 参数。普通发布和存档QA预设继续使用自己的入口。

    导出程序留在忽略的 .godot/road-performance-* 目录，证据目录保存：

    • source-manifest.json、runner-manifest.json：构建输入及驱动脚本的哈希。
    • binary-manifest.json、managed-identity.json：实际EXE、依赖和两个游戏程序集的哈希，以及直接读取PE元数据得到的编译配置、优化标记。引擎非Debug不等于所有依赖已优化；发现未优化程序集立即拒绝采样。
    • run-plan.json、run-result.json：请求的数据集/时长/轮数、实际退出码、超时和二进制未改变检查。
    • 每套数据的 render-*.json：全部逐帧序列、P95/P99/最大值、超预算数量、输入到正确token首次绘制的响应和分阶段指标。四类持续窗口各运行指定秒数；编辑与取消窗口按操作数量结束，实际时长单列。预热/准备操作仍保留在原始数据和汇总中。
    • foreground.json：约50ms一次的Win32前台句柄与所属PID；启动/退出期间的其他PID也保留。验收要求从首个测量窗口到最后窗口之间的所有原生采样属于被测进程，首尾缺口及相邻轮询间隔不超过250ms；同时逐帧要求引擎焦点成立。短取消窗口可能没有独立原生轮询，不能宣称观察到了小于轮询间隔的焦点变化。
    • summary.json、summary.log：重算帧统计、程序集与载荷身份、完整窗口/操作数、前台覆盖、P95≤6.9444ms及重复操作响应≤300ms等检查。任何失败保留原始数据并返回非零。

    再次复核：

    python Scripts/QA/summarize-road-release.py $releaseOutput

    复核会重新哈希实际导出文件。如果 .godot 下二进制已清除，旧哈希只能作为当时的记录，无法通过本命令的当前身份验证；应重新导出采样。P95通过也不等于没有卡顿，必须公开P99、最大帧和全部长尾。Release输入注入与原生前台证据不替代编辑器/DAP验收；本工具不关闭GitHub工单或批准产品预算。

    完整 CLR 跟踪¶

    使用包含 collector 握手的新性能导出包。游戏在全部测量窗口关闭后发布带唯一 token/PID 的 ready 标记，等待采集端完成；采集端通过 Microsoft.Diagnostics.NETCore.Client 主动 StopAsync、排空流并确认结束标记，再原子发布确认文件。游戏确认后清理存档并退出，等待阶段不加入测量窗口。

    先用上面的导出流程取得 binary-manifest.json。下面的两个程序集来自 dotnet-trace 工具包；路径按本机实际安装填写，不需要全局安装。

    $clrOutput = ".scratch/road-clr-$runTag"
./Scripts/QA/capture-road-clr.ps1 `
  -Manifest "$releaseOutput/binary-manifest.json" `
  -Datasets .scratch/v4-24-20260930/datasets `
  -DiagnosticsClientAssembly '<工具目录>/Microsoft.Diagnostics.NETCore.Client.dll' `
  -Output $clrOutput -AttachInputAtStartup `
  -Cell 25 -Dataset target -WindowSeconds 2 -WarmupSeconds 5 -Cycles 10 -SettleSeconds 5

./Scripts/QA/read-road-clr-events.ps1 `
  -Trace "$clrOutput/gc.nettrace" `
  -Output "$clrOutput/gc-events.json" `
  -TraceEventAssembly '<工具目录>/Microsoft.Diagnostics.Tracing.TraceEvent.dll'

python Scripts/QA/validate-road-clr.py $clrOutput

    当前验证过的工具程序集版本为 Diagnostics.NETCore.Client 0.2.745401、TraceEvent 3.1.23。结构检查针对当前运行时输出的 v4 FastSerialization Trace 头；遇到未知格式会拒绝，不能自动补字节后当作原始完整流。

    capture-road-clr.ps1 记录真实二进制/托管优化身份、数据集身份、GC 子进程参数、前台/资源采样，以及 Stop 请求、完成、排空和确认时间。默认不覆盖 GC 模式；GcMode、GcDatas、GcHeapCount、GcMaxHeapCount 仅用于显式诊断对照，不改变项目配置。

    检查器分别验证运行时、前台、窗口/操作完整性、握手身份与顺序、完整结束标记、覆盖末尾窗口的最终序列点，以及实际解码的 PID 和丢失计数。文件能解析不等于性能通过；如果运行时或前台失败，仍返回非零并保留证据。追踪数据不与无插桩性能混算。

    不传 --collector-token 时测试主循环沿用原来的退出行为。显式启用握手后，缺少确认、错误 token/PID、失败确认或超时都会使场景失败；临时槽仍走正常清理。旧导出若忽略该参数，采集入口会因缺少握手而拒绝，须重新导出。

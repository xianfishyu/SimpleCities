    V4-20 当前容量性能与历史资源基线¶

    测量日期：2026-09-29；对应 GitHub #21。起点：feat/road-network-v4 的 2b942a922bc0a3303bb80287d695385ecfb001b6（#19/#20 检查点）。 本报告对应此次工作区实现和新采样，不沿用回退前提交、旧报告或评论中的通过状态。

    结论与范围¶

    四档当前容量夹具的加载、可见高亮、真实输入编辑、历史和取消检查共 1816 项通过；共记录 673050 帧、1444 次输入到正确首绘响应。全部窗口 P95/P99 小于 6.9444ms，响应最大 93.2688ms，当前样本满足不超过 100ms、因而也满足 300ms 的响应上限。但仍有 46 帧超过 144 FPS 的 6.9444ms 帧预算，最慢 73.352ms；持续 144 FPS 未验收，10K/9680 目标规模未验收，正式场景切换未解锁。

    当前生产限制仍为 512 节点 / 256 规范边 / 2048 链点 / 1MiB 载荷。本票测量当前可构造规模并输出后续证据；没有提高上限或实施未知优化。正式主场景仍为 V3，测试使用隔离 V4MapTest。

    原始载荷、逐帧时间、操作 token、分阶段时间、历史实验、命令日志与编辑器证据在 .scratch/v4-21-20260929（归档原路径：.scratch/v4-21-20260929）。完整窗口和操作分组见 summary.md（归档原路径：.scratch/v4-21-20260929/summary.md），可由同目录 summarize.py 从原始 JSON 重算；复跑说明定义了测量边界。

    计数与可构造性¶

    10K 固定为 RoadSnapshot.EdgeCount，即规范道路边，不是主格点、路口、用户笔画、网格跨段、链点或三角形。25/50/100 米目标各 10000；200 米目标为用户已确认的 9680 边满铺。

    8×8km 地图每边 n=8000/cell 个格子。完整米字格含 2n(n+1) 条水平/垂直边与 4n² 条经格心分割的对角边，合计 6n²+2n；这是该合法完整格架的几何计数，不能代替当前生产准入或实际构造测试。

    格长 每边格数 完整格架规范边 已确认目标 100K 几何规模 本次实际载入
    25m 320 615040 10000 格架容量足够；未构造/未加载 240 混合边，另 20 折线边
    50m 160 153920 10000 格架容量足够；未构造/未加载 同上
    100m 80 38560 10000 超过完整格架计数；不凑数 同上
    200m 40 9680 9680 超过完整格架计数；不凑数 同上

    实际夹具仅用公开 PlanBuild/TryCommit 构造，逐档严格 codec 往返，再通过正常 SaveManager 槽位装载到真实 Vulkan 场景。四档分别有核心行为测试，不绕开 RoadTopology/codec 限制：

    夹具 规范边 节点 格心路口 链点 折线边 网格跨段 表现片 顶点 / 索引
    mixed 240 109 36 492 12 252 1124 3624 / 4128
    polylines 20 40 0 820 20 800 3920 12560 / 14160

    mixed 为 6×6 完整米字格加 12 条独立 L 形折线；polylines 为 20 条各 40 段的独立折线。典型建造固定为四跨段（各档 100/200/400/800m），拖选固定为三个跨段。每轮建造/改造/删除及对应撤销、重做最后恢复原始夹具，共 30 轮；每档另建一次取消夹具，所以首绘样本为 361。

    环境与采样¶

    • CPU：AMD Ryzen 9 9950X3D，16 核 / 32 逻辑处理器；物理内存 50618658816B。
    • GPU：NVIDIA GeForce RTX 5080，驱动 32.0.16.1664，Vulkan 1.4.351。
    • Godot 4.7 stable mono official 5b4e0cb0f，Forward+，1600×900，VSync 关闭，Engine.max_fps=0。
    • GPU 数据来自可见窗口的独立 Godot Debug 引擎 / Debug C# 运行，核心历史工具为 .NET 10.0.12 Release；DOTNET_TieredCompilation=0。ExportRelease 编译通过另行记录，未把它称作导出包性能样本。
    • 每档独立进程；mixed 与 polylines 各预热 5 秒。静止、相机、可见高亮、相机加高亮、折线静止/相机各采 10 秒；相机/鼠标按 60Hz 输入。编辑与取消窗口按固定次数结束，实际秒数见 summary.md。
    • 逐帧以 RenderingServer.frame_post_draw 的单调墙钟差取样，最近秩分位数，不裁剪异常点。每帧记录引擎窗口焦点，673050/673050 帧均聚焦；没有把这一点升级为导出 Release 的原生前台 PID 验收。
    • 首绘需操作 token 改变、表现 token 匹配、BuildPhase=Drawn 且表现 Current。计时从实际处理输入开始；注入到测试协程观察完成的时间另列，避免把两种口径混用。
    • 阶段时钟有常驻的少量读取成本；指标字典只在每次操作结束时读取。当前观测入口不提供无开销推断。

    64 笔历史与取消清理¶

    每个格长每种场景预热一次、测三次，共 48 组，每组保留 64 笔。实验保持同一个当前 snapshot 强引用，只释放持有历史的 network；弱引用确认 history 可回收。完整前后托管存活字节、分配量、64 笔操作时间和强制 GC 时间均保留在 core-baseline.json。差值不取绝对值，也不把进程工作集当作独占历史内存。

    场景 64 笔领域估算 B 边际托管保留 B 最大单笔增量估算 B
    mixed 单跨段改造 28672 29864 448
    mixed 全 252 跨段改造 3969024 2866176 62016
    mixed 每笔三跨段删除 74560 100728 2848
    820 链点折线全 800 跨段改造 1937408 1053088 30272

    同场景四档三次的字节差相同；最大领域估算约 3.785MiB，边际托管保留约 2.733MiB。删除场景保留相同的最终 25 边快照作对照。单段改造和批量删除的实测保留高于领域估算，因此估算不是托管堆上界；共享当前快照的空间被保留在前后两边，不重复归给历史。

    清理边界 样本与结果 最大 ms 限制
    核心 token 到 worker 退出 40/40 实际抛出取消，状态不变 3.1142 worker 进入即请求，不代表最深算法阶段
    Godot Esc 到 worker 退出 80/80 接受取消 1.1751 真实 Ctrl-Z 后 Esc；该样本无提交竞态
    Godot Esc 到工具可用 80/80，活动状态不变 1.4851 与 worker 边界分开
    已准备未提交候选释放引用 20/20 弱引用回收，旧 network 不变 0.0758 不包含 GC 时间
    上述候选实验强制 GC 最大边际空间 144952B 0.2572 仅实验成本，不是生产清理承诺

    初次核心取消实验在 worker 进入后等待 1ms，40/40 都在请求前完成，未用作取消达标证据；最终改为进入即发 token 并保留竞态分类。生产没有增加强制 GC。

    候选预算继续提交给 #26 确认：累计领域估算 8MiB、单笔 256KiB，分别约为本次最大估算的 2.1 倍与 4.2 倍；仅适合作为下一轮压力试验/报警候选，不能外推到 10K 或视作真实堆上界。建议累计超限按最旧历史逐笔裁剪，单笔自身超限在提交前明确拒绝、保留活动快照与历史，不静默提交无历史编辑；这些产品行为尚未获确认，未写入生产。核心取消 10ms 仍为候选；Esc 工具恢复可用 100ms 作为下一轮观测候选，两者须分别确认，未承诺自然 GC 在固定时间完成。

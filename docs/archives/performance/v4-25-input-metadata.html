    V4 持续输入与绘制的元数据分配¶

    诊断开始：2026-10-05；最终实现与编辑器验证：2026-10-07。 基线 43a5f188；证据 .scratch/v4-input-allocation-20261005/；关联 #25。

    已确认的问题与改动¶

    持续相机、可见悬停和联合输入的完整 CLR 分配栈观测到重复的 RoadStateToken.PrintMembers、V4MapView._Draw 字符串分配，以及输入中的 Godot 包装对象。记录查询时原先立即格式化 token；每次重绘又格式化同一个 token；建造 hover 还通过公开 PickRoad 创建仅供诊断的 Dictionary 和来源字符串，再解包读取参数。

    • 查询状态保存 token 值，仅在 DescribeQuery 时按原格式生成字符串。未查询时仍输出空字符串，失败查询仍保留对应来源和状态。
    • 绘制字符串按完整 token 缓存，包括 lineage 和变更序列；只有实际成功绘制才发布 DrawSubmittedToken。失败回退重新取得旧表现的 token，不把缓存字符串当作已绘制证明。
    • 建造 hover 直接读取同一查询器的类型化命中结果；仍先更新格段选择，仅在 Ready 且有命中时更新原路口/格心方向数或道路位置文本。公开诊断 PickRoad 不变。
    • HUD 面板在 _Ready 缓存，输入热路径复用节点，避免反复构造 NodePath。没有改变跨 UI 松开、取消或显示准入规则。

    固定分配回归与功能¶

    Debug 专用探针预热后复用一个鼠标事件，分别直接调用场景的两个真实输入处理器 1,000 次；测量后才读诊断字典。它测量处理器分配，不包含完整 Godot 输入桥、逐帧绘制或 GPU 时间。

    模式 旧分配 B token/HUD 缓存后 B 最终类型化读取 B
    建造 8,904,000 5,976,000 3,232,000
    选择 5,057,808 2,176,000 2,176,000

    最终固定门为每事件建造 4 KiB、选择 3 KiB。首次原实现均失败；建造门在类型化读取前再次失败，之后通过。全部检查当前查询来源、悬停和源路网未变。另通过实际 Input.parse_input_event 验证普通路口“3 个方向”、格心路口“4 个方向”，道路位置保持“40%”；每次实际绘制 token 与活动 token 一致。

    Core 410/410、Application 968/968；Debug/ExportRelease 0 警告/错误；改动 C# 的 Roslyn 及全方案分析器无诊断，GDScript 诊断为空。实际显示/分页/失败回退 417 项、格段选择契约通过。最终 Standards 和 Spec 审查各 0 项可行动发现。

    编辑器正常启动当前代码，五套容量 159 项、46 次操作通过，实际 DAP 收到开始及五套完成标记，stderr 为空。追加类型化拾取验证通过真实输入得到“道路位置：40%”，当前查询、表现和绘制来源一致。首次 exec 在游戏桥启动时超时；随后只读状态确认没有执行设置，待桥就绪重试成功，原失败保留。第二次 DAP 附着有重复 stdout 条目，按同一打印去重，不计为额外场景。游戏和临时节点已停/清理，临时槽已删除，编辑器自动重写的场景已保留后恢复。

    Release 分配与暂停¶

    同参数 25 米 / 10K：5 秒预热，四个持续输入窗口各 30 秒，30 轮编辑和建造，1 秒 settle。相邻重跑旧二进制、仅缓存中间版、最终类型化版，各 480 项、360 次测量操作通过，原生前台有效，CLR 流完整且无丢失。源码与实际优化二进制哈希分别保存，不将三版混用。

    分配 tick 加权估算 旧版邻近重跑 仅缓存中间版 最终版
    相机 30 秒 B 18,599,192 9,351,144 6,111,144
    可见悬停 30 秒 B 10,224,152 4,828,968 4,565,792
    联合输入 30 秒 B 16,690,432 8,621,368 9,103,912
    测量最大帧 ms 28.880 30.596 23.772
    超预算帧 2 1 2

    tick 权重是估算，单个类型/方法排名有采样波动，最终联合输入估算比中间版略高。直接处理器回归提供独立的确定分配证据，不能把上述估算当作精确逐类型总量。

    旧版联合输入出现 Gen1 完整暂停；中间版和最终版本批持续输入窗口没有同类长帧。最终版的两个长帧均在编辑阶段：23.772/11.648 ms，分别与 23.118/11.008 ms 完整 GC 暂停重叠，保守对齐后仍由暂停占主导。测量输入到首绘最大 41.5624 ms，包括 setup 71.6191 ms。这证明持续输入分配下降，不能证明所有长尾已消失，也没有修改 GC 默认值。

    当前代码的无跟踪持续复验¶

    首次最终无 CLR 对照发生大量失焦，八个阶段的焦点门均失败，原始数据保留，其功能和 P95 检查虽通过，仍不作为正式性能通过证据。用户随后提供连续窗口，另用同一最终二进制完整重跑五套数据，5 秒预热、四个持续输入窗口各 30 秒、编辑和建造各 30 轮、20 次 Esc、1 秒 settle。

    数据集 帧数 最高阶段 P95 / P99 ms 最大帧 ms 超预算帧 测量首绘最大 ms
    25 米 / 10K 330,596 1.121 / 1.640 29.832 2 29.271
    50 米 / 10K 332,913 1.370 / 1.685 29.323 2 46.059
    100 米 / 10K 333,117 1.129 / 1.662 30.597 1 48.326
    200 米 / 9,680 334,171 1.111 / 1.702 29.653 1 42.718
    200 米 / 补充折线 344,569 1.080 / 1.230 8.536 2 13.139

    共 2,378 项、1,675,366 帧、1,812 次操作（1,800 次测量、12 次 setup）。全部引擎焦点和原生前台有效，所有组都有建造/历史窗口。100 次取消均为 ExitedBeforeRequest，工具恢复最大 0.872 ms，没有警戒线超限；worker 的实际计算取消仍采用独立核心探针证据，不把提前退出的零值当作预算通过。

    verify-formal.py --verify-live 检查完整参数、实际数据计数、来源身份、每种建造历史操作各 30 次以及逐帧分位数/最大值/超限计数。verify.py --verify-live 另核验所有 CLR 捕获和失败对照，现记录 untracedControlVerified=true。相较修改前完整矩阵的最大帧 26.887 ms，当前最大 30.597 ms 更高；不能把分配下降外推为整个最大帧时间改善。残余编辑暂停继续单列，不仅凭 P95 收口。

    完整原始跟踪、大型 JSON 和失败对照已无损归档，逐文件验证解压字节与 SHA256，原始文件本地保留。新增两个 QA 脚本的导出过滤遗漏已修正，原失败和随后 Application 全套通过记录均保留。

    持续输入的局部分配重构及当前五场景吞吐/响应数值门已验证。残余编辑暂停、导出初始化、#22 正式切换和 #23 旧路径清理仍开放，不追加整个长尾问题关闭记录；没有推送或远程工单修改。

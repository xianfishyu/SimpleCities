    V4 历史策略与取消警戒线¶

    日期：2026-10-04；关联 GitHub #26。本文记录当前用户决定及本地证据，不代表远程工单已更新或全部验收完成。

    已确认的产品行为¶

    用户在说明字节拒绝门含义后明确选择：不因大小拒绝编辑，只限制 64 笔。

    • Undo/Redo 共用最近 64 笔有效编辑；第 65 笔淘汰最旧记录。撤销后另做编辑丢弃原重做分支，再按条数裁剪。
    • 不设累计或单笔历史字节上限，不因历史估算大小拒绝编辑，不将合法编辑静默变为不可撤销。道路自身的几何、容量和版本检查继续执行。
    • 失败、取消及无变化不计入历史。成功编辑与对应历史原子发布；新地图和加载后历史清空，调试存档不保存历史。
    • RoadEditHistory.EstimatedBytes 是领域载荷估算，仅作观测。跨记录共享的实体重复计数，不包含活动快照、派生索引或 GPU 资源，不能解释为真实堆上界。

    此前候选 8 MiB/256 KiB、256 MiB/4 MiB 不采用，V3 的 16 MiB 规则不迁入。现有核心 RoadEditHistory.Capacity = 64 及按条数裁剪的行为与决定一致，无需增加字节拒绝分支。

    用户同时确认：核心 token 发出到 worker 退出以 10 ms 为警戒线；Godot Esc 输入到工具恢复以 100 ms 为警戒线。超时保持“正在取消”直到安全清理完成，不伪报完成、不强杀线程。保留每个超时样本并继续定位；提前完成和提交竞态单独分类。未提交计划失去引用与 GC 自然回收是不同边界，生产不主动强制全代 GC。

    目标规模历史初测¶

    原始数据：.scratch/v4-completion-20261004/history-targets.json，脚本 HistoryProbe.csproj / Program.cs。使用 .scratch/v4-24-20260930/datasets/ 的合法 Codec 数据，25/50/100 米为 10,000 条规范道路边，200 米为 9,680 条满铺边及 320 条密集折线。

    每套数据实际提交 64 笔局部改造、128 格批量改造、每笔删除 3 格及全图类型改造，共 20 个场景。Release 关闭分层编译以稳定实验中局部变量的存活范围，保留同一当前快照，比较释放 owning network/history 前后的托管存活空间；弱引用确认全部历史已回收。强制 GC 仅用于诊断进程，不计入取消延迟，也不加入生产。

    场景 64 笔领域估算 MiB 边际托管存活 MiB 最大单笔估算
    25/50/100 米局部改造 约 0.027 约 0.029 448 B
    25/50/100 米批量 128 格改造 约 2.012 约 1.522 32,960 B
    25/50/100 米每笔删除 3 格 约 0.047 约 0.072 1,616 B
    25/50/100 米全图改造 156.887 117.899 2,570,432 B
    200 米满铺全图改造 151.262 113.824 2,478,272 B
    200 米密集折线全图改造 5.637 4.092 92,352 B

    这些是各场景单轮测量；不是进程工作集、历史独占内存的精确值或最终内存上界。需补充简单建造、高链点最重操作、实体共享计数及重复释放/取消的边界证据。该初测曾用于解释预算候选，不改变用户最终选择。

    取消计量与已验证的边界¶

    GetOperationMetrics() 现明确区分未请求、等待 worker、请求前已退出和请求后退出；0 ms 不再独自代表取消响应达标。token→worker 的计时起点仍为发出取消，Esc→工具恢复从 Godot 接收该输入开始，覆盖选择清理、worker 退出、候选清理、编辑门释放和实际按钮属性恢复。这里的工具恢复指输入门和控件可用，不是显示器扫描完成；退出场景不报告工具恢复。

    生产只增加已确认的 10/100 ms 警戒线观测及是否超限字段，不按超时强杀、不提前解锁。UpdateOperationControls() 同时服务普通帧刷新与结束清理，避免编辑门已恢复而按钮仍留到下一帧更新的计量缺口。

    真实 Godot 的 v4_async_operation_runtime_contract.gd 通过以下确定性场景，原始输出在 .scratch/v4-completion-20261004/cancellation-final-console.log：

    • 人为留住 worker 约 150 ms：期间保持 Cancelling、输入写入门关闭，worker 为 Pending、工具恢复未观测。释放后分别记录 156.040 ms / 160.675 ms，两个超限标志均为真，路网不改变。这是故障注入的超时处理证据，不是正常运行延迟。
    • worker 已完成而主线程 continuation 尚未发布时注入真实 Esc 事件，得到 ExitedBeforeRequest、worker 0 ms、工具约 1.701 ms；候选不发布。测试中的主线程等待只用于固定竞态，不进入生产。
    • 继续通过提交前立即取消、晚到结果拒绝、提交胜出后 Esc 不撤销、首帧前保持独占及退出场景后拒绝晚到发布。

    随后独立 ExportRelease 25 米/10K 短窗口通过 125 项检查、60 次正常操作，另有 20 次取消尝试：19 次接受取消且全部是请求前 worker 已退出，1 次提交先胜出并按 Drawn 记录。后者没有伪造取消时间（保留 -1），测试明确重置其内容后继续。19 次工具恢复最大 1.346 ms，无警戒线超限；这批数据不能证明深度计算期间的 worker 退出预算。原生前台 self/other 97/0，最大轮询间隔 82 ms。二进制身份、每帧统计和分类由 verify-cancellation.py 验证；分析器初稿错误要求所有尝试均取消，已修正为分别验证提交竞态，没有删改原始样本。

    Debug/ExportRelease build 为 0 警告、0 错误，改动 C# 的 Roslyn 诊断及全方案分析器为空。历史/资源重用回归本次 92 项通过（未重复可选的 10K 分配探针）；Application 初跑有一个既有零分配断言报告 7,296 B，未改源码或断言，隔离 2/2 及完整 968/968 复跑通过；根因未确认，失败日志保留。本次核心库未再更改，沿用同次工作先前 383/383 的结果。

    本会话仍无 Godot editor/minimal MCP，编辑器/DAP 门未完成；独立运行游戏日志无错误。导出日志仍有主场景 UID 初始化、6550 端口占用和 ImGui GDExtension 错误，退出码及实际优化二进制/Release 运行通过。依据 bugfix-recorder 的 “If verification is blocked or failing, report that status to the user instead of creating a completed bugfix record.”，不把这些局部验证记作完整 Bug 关闭。

    剩余验收¶

    26 的产品决定已解除等待确认；64/65 笔与分支/加载回归已在本轮核心及实际 Godot 检查通过。目标规模审计 补充 87 组历史测量、280 次取消尝试和 70 次候选释放，含共享计数、高链点、上限路网及已弃用字节预算的反例。已有 64 笔大记录时 Undo 的估算重扫已修复并复验，但缓存失效重建仍有 15.576/63.361 ms 两个取消超时，需继续定位并保留等待/清理状态。#25 帧时间和响应长尾、编辑器门及 #22/#23 切换清理不由本文代为完成。¶

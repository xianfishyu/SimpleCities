    V4 目标规模历史与候选生命周期审计¶

    日期：2026-10-04；关联 GitHub #26；生产检查点 9cc3d3e2。 原始证据：.scratch/v4-26-audit-20261004/；执行入口：SimpleCities.RoadCore.Performance --history-policy。 产品规则仍为仅保留最近 64 笔、不按字节拒绝，取消警戒线为核心 10 ms、Godot 工具恢复 100 ms。

    数据与方法¶

    本轮使用全部五套 #24 合法数据：25/50/100 米各 10,000 条规范道路边，200 米满铺 9,680 边，以及 320 条密集折线。另补充两套严格 Codec 验证的数据：25 米单条非自交折线含 10,272 个链点；25 米 16,384 边上限路网由公开 PlanBuild/TryCommit 构造，包含 52×52 米字格网及 56 条独立道路。补充夹具是资源审计输入，不把 16,384 边改称产品 10K，也不将其作为新容量或 FPS 承诺。

    每个历史场景预热一次，再测三轮实际 64 笔操作，共 87 组测量。覆盖单格改造、128 格批量改造、每笔删除 3 格、全图类型改造；25/50/100 米目标及 200 米折线另覆盖 64 笔建造。满铺 200 米与边数上限路网不强行增加非法道路。

    测量前对 history delta 的 before/after 引用槽按对象身份去重，并记录与同一个当前快照共享的实体。计数集合在进入堆测量前释放；保留该当前快照，释放持有历史的 network，比较强制 GC 后的有符号托管存活差。每次弱引用都确认历史回收。记录领域估算、引用释放以及 GC 耗时；进程工作集不是本报告的历史成本，强制 GC 不进入生产，也不计作取消或 Dispose 延迟。

    64 笔结果与字节规则反例¶

    全图改造场景 领域估算 MiB 边际托管存活 MiB 最大单笔估算 B 引用槽 / 不同 Edge 对象 / 与当前共享
    25/50/100 米各 10K 156.887 117.899 2,570,432 1,280,000 / 650,000 / 10,000
    200 米满铺 151.262 113.824 2,478,272 1,239,040 / 629,200 / 9,680
    200 米密集折线 5.637 4.092 92,352 40,960 / 20,800 / 320
    10,272 点长折线 20.086 10.058 329,088 128 / 65 / 1
    16,384 边上限路网 256.012 192.642 4,194,496 2,097,152 / 1,064,960 / 16,384

    全图类型改造不改变结构节点，所以这些行的 Node 引用槽均为 0；建造与切分场景的 Node 槽和共享数另在原始 JSON 中。三次估算及共享计数一致，边际存活结果基本一致，上限路网三次差异为 24 B。这里的三轮重复不提供跨硬件或跨运行时的真实堆上界。

    10K 路网的 64 笔局部改造约 28,672 B 领域估算；128 格批量改造 2,109,440 B；每笔删除 3 格累计 48,864 B；64 笔建造累计 31,744 B。高链点折线每笔删除 3 格累计估算 20,877,312 B，实际边际存活 10,464,928 B，说明操作格段数少不代表其完整不可变几何载荷也小。

    16,384 边每笔全图改造比未采用的 4 MiB 候选多 192 B，64 笔累计比未采用的 256 MiB 候选多 12,288 B；每笔均成功提交且保留 64 条历史，证明当前代码未引入这两个字节拒绝门。所有七套数据另实际执行第 65 笔、64 次撤销和 64 次重做，最旧可达 content revision 精确对应第 1 笔后的状态，最终恢复第 65 笔；只淘汰最旧记录。

    计算中的取消与未提交候选释放¶

    每套数据执行 40 次全图改造取消尝试，共 280 次。诊断输入枚举器在选择复制结束时发出观察信号，再延迟 0/1/5/15 ms 发 token，各 10 次；实际延迟和 worker 内的 finally 时间都保留。这个信号不定位到某个精确拓扑子阶段，不把等待线程观察 Task 完成的时间当作 worker 退出时间。

    • 241 次实际观察到取消：token→worker 退出 P95 1.092 ms、P99 1.996 ms、最大 2.590 ms，没有超过 10 ms 警戒线。
    • 39 次请求前已退出：200 米短折线 29 次、高链点折线 10 次，单独分类，不将它们的 0 ms 混入上述分位数。
    • 全部尝试都没有提交，源 snapshot 和历史对象保持同一引用；未出现请求后正常完成的竞态。本轮记录方法保留该类别，若后续出现仍应原样报告。

    每套数据还保持源 network 存活，依次准备并释放 10 个未提交计划，共 70 次。plan、目标 snapshot 和 change set 的弱引用全部回收，源 snapshot/history 保持不变。释放引用最大 0.232 ms；诊断 GC 最大 6.818 ms，两者不是同一指标。该结果说明观察到的候选没有持续被生产网络持有，不是固定时间自然回收保证，也不代表 Godot 资源释放已经由纯核心实验验证。

    验证与剩余边界¶

    python .scratch/v4-26-audit-20261004/verify.py --verify-live 通过：核对全部样本、重复次数、七套数据的哈希及计数、64/65 笔证据、字节反例、生命周期、分类和警戒线，并核对实际测量使用的源码/程序集身份。去掉 --verify-live 只验证归档数据；二进制被后续构建替换时不能继续声称其身份已实时复核。

    独立 Release 基准项目与主方案构建均 0 警告、0 错误。基准项目不在主方案中，使用临时 Roslyn 方案检查新增入口与辅助类，编译器诊断为空，之后卸载并恢复主方案。该临时方案未授信，所以没有运行它的附加分析器；主方案分析器诊断为空不冒充该工具的分析器覆盖。本次只添加独立测量工具和文档，没有改 Godot 生产行为，不重复 GPU/编辑器测试。

    本审计补齐目标规模资源、简单建造、高链点、共享计数、65 笔裁剪及重复候选释放证据。随后针对已有 64 笔大记录的 Undo 发现估算重扫并完成修复与完整复验，新记录固定增加少量元数据；缓存失效时仍有两个取消超时，不能直接把本页空历史全图改造的成绩推广到该路径。Godot 层的确定性竞态、超时提示及 Release 工具恢复证据见策略报告；编辑器/DAP 门仍不可用。远程 #26 未修改或关闭，#25 长帧与正式切换/清理仍另行推进。

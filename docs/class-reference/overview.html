    SimpleCities 类参考¶

    本目录参照 Godot 官方类参考编写：每种类型有独立页面，先说明用途与继承关系，再用成员概览定位到详细说明。接口名称保留项目的 C#、GDScript 或 Python 拼写，正文使用中文。

    排版改版日期：2026-11-03。源码内容沿用 2026-10-26 的基线，本轮重新核对声明结构与摘要；不表示重新通过游戏或性能验收。结构、说明与来源映射保存在 coverage.json。

    阅读入口¶

    要查什么 入口

    地图、模型、规划、历史与空间查询 道路纯核心
    场景装配、表现资源和拾取 Godot 运行适配
    保存、加载、槽事务与操作协调 持久化
    HUD、建造坞、暂停及上下文 界面

    单元测试、性能辅助类与 Debug 探针 测试与诊断
    GDScript 和 Python 命名类 其他语言

    系统行为与设计取舍由工程架构、道路、存档、UI等手册维护；本目录解释具体接口，集中链接到拥有相应规则的页面。

    页面怎样组织¶

    1. 按模块分目录，按类型分正文页。 class、interface、record、struct、enum 和 delegate 都有独立页面。RoadNetwork.cs 中的 RoadNetwork、RoadSnapshot、RoadPlan 和 RoadStateToken 各自成页；源码文件数量不决定文档页数。
    2. 合并同一类型的 partial。 RoadMapScene、RoadDisplay 等只保留一个完整类型视图，源码栏列出全部分部，包括标明 Debug 边界的探针补充。
    3. 嵌套类型有独立参考，也从外层进入。 外层页按 Godot 信号、枚举和其他嵌套类型提供导航。顶层 C# enum/interface/record 以及嵌套辅助类型独立成页，是本项目为完整覆盖所做的适配；Godot 原生枚举通常直接列在所属类页。
    4. 测试使用相同页面规则。 测试模块按完整类型名分页面，原测试集合页保留为导航入口。原 RoadModel、SaveData 等源码集合页同样保留导航，不重复维护类型正文。
    5. 每个成员都有稳定锚点。 概览表中的名称链接到详细说明，重载保留各自完整声明和参数表。原有类型和成员锚点在新的所属页面继续使用；仓库内引用同步到独立页面。

    页面内容与写法¶

    页面按适用情况包含：

    • 类型名、实际继承/实现关系、外层及已知派生/实现类型、简介、种类、声明可见性与命名空间。
    • 描述：实际职责、持有关系、生命周期、线程和来源身份约束；必要时给注意事项，避免为所有类型重复无关规则。
    • 教程与示例：链接系统手册和项目调用示例。
    • 属性、字段、构造函数、方法及运算符概览：返回类型、名称、参数、源码初始值或实际限定符。
    • Godot 信号、C# 事件、枚举、常量及其说明；没有对应成员的章节省略。
    • 属性、构造、方法等逐项详细说明：完整声明、已有行为解释、参数类型与默认参数、源码位置。
    • 折叠的私有实现参考，保留维护所需的全部显式声明。

    只把真正的 [Signal] 委托称为 Godot 信号，普通 event 明确列作 C# 事件。只把 [Export] / ExportAttribute 成员作为导出配置；ExportGroup 和 ExportSubgroup 是 Inspector 分组，不使字段自动导出。

    默认值仅来自实际源码初始化或构造参数。未显式初始化、由构造或运行决定的属性不猜默认值；场景/资源可以覆盖导出配置。static、async、virtual、override、readonly 及访问器保留实际 C# 含义，不把 Godot 的 const 方法限定符移植成项目保证。

    位置 record 的生成属性和主构造函数另列说明，不计入显式成员数量。声明可见性受外层类型约束；有 public 成员的私有辅助类仍不是外部 API。没有独立行为说明的成员明确标出并链接源码，排版生成不能代替补写真实契约。

    官方参考依据¶

    本次核对了官方 Node、Resource 和 Vector2 页面，以及 XML schema 与生成器。借鉴的是独立类型页、简介/描述、继承关系、概览到详细说明的导航和按成员种类分组。

    这里继续使用 Markdown。纯 .NET 类型、C# 接口与位置 record、所有非公开和测试类型的收录规则属于项目适配，不是 Godot 对第三方项目的强制格式；官方页面中的引擎行为也不自动成为项目接口契约。

    维护与检查¶

    coverage.json version 2 同时保存已审核的声明结构、来源摘要及人工说明。类型的 description / remarks 和成员的 description 是正文编辑入口；render_class_reference.py 生成类型和导航页。首页及 usage.md 继续手工维护。

    # 修改已审核的结构或说明后生成页面
python Scripts/Docs/render_class_reference.py

# 只检查，不改文件
python Scripts/Docs/render_class_reference.py --check
python Scripts/Docs/check_class_reference.py
python Scripts/Docs/check_docs.py
git diff --check

    源码改动后先通过 Roslyn 语法树或语言服务更新相关类型的声明、参数、访问器、默认值和行号，再人工核对行为说明与示例，最后更新对应源摘要并生成页面。渲染工具不会提取新源码、批准行为或自动修改摘要，不能只换摘要使检查通过。摘要使用去 BOM、CRLF 规范化为 LF 的 UTF-8 字节。

    覆盖检查核对当前源码、独立类型页、稳定声明锚点、签名和生成页面同步；链接检查核对本地文件与支持的 Markdown 锚点。这些检查不证明逐方法行为、Godot 图形或性能通过，运行验证仍按验证手册执行。

    网页浏览与部署¶

    站点使用同一批 Markdown，提供分类导航、中英文搜索、页内目录、代码复制、明暗主题与源码行查看。在线入口为 GitHub Pages。

    在仓库根运行：

    # 首次运行会创建独立环境并安装固定版本依赖，之后构建并启动本机预览
./Scripts/Docs/serve_docs.ps1

# 只生成静态站点和可独立部署的 zip
./Scripts/Docs/serve_docs.ps1 -BuildOnly

# 预览最近一次成功构建，按 Ctrl+C 停止
./Scripts/Docs/serve_docs.ps1 -NoBuild -Port 8765

    构建结果及 zip 路径记录在 .scratch/docs-site/current.json。每次构建使用新的输出目录；部署只需记录中 site 指向目录的静态文件，不需要 Python 服务端。脚本绑定 127.0.0.1，默认本机地址为 http://127.0.0.1:8765/SimpleCities/。

    GitHub Pages 使用专门的 codex/gh-pages 发布分支，并保留 .nojekyll。发布该分支与提交源码分支是分别授权的 Git 操作。构建会检查声明与页面同步，并核对生成 HTML 的本地链接和锚点；原始大型运行证据、忽略文件和未打包资料只生成引用说明，不随站点发布。

    得到发布授权后，运行 ./Scripts/Docs/publish_docs.ps1 构建并发布，或用 -SkipBuild 发布最近一次已通过检查的构建。发布工具只更新独立发布分支，保留它的提交历史，不推送当前源码分支；遇到其他工具管理的站点会停止以保留其内容。

    发布工具沿用当前环境或 Windows 已配置的 HTTP/HTTPS 代理，仅通过当次 Git 命令参数传入，不写入全局 Git 或系统设置。连接异常时可先运行 ./Scripts/Docs/publish_docs.ps1 -SkipBuild -CheckConnection，此模式只读取远程 HEAD，不发布内容。

# RoadGraph V2 性能基线

> 采集日期：2026-08-03
> 环境：Microsoft Windows 10.0.19045；.NET 10.0.0；32 logical processors
> 命令：`dotnet run --project tests/SimpleCities.RoadGraph.Performance/SimpleCities.RoadGraph.Performance.csproj --configuration Release --no-restore`

## 数据集与口径

- 固定数据集由互不连接的水平直线 Edge 组成，Edge 间距 32 单位、长度 8 单位，规模分别为 1k、10k 和 100k。
- 短路、长路、原生 cubic Bézier、完整覆盖、多交叉、最近边命中和单边删除使用确定坐标；每个样本从相同 JSON 恢复图，恢复和 GC 不计入操作耗时。
- 1k 和 10k 每个场景预热一次，分别采样 8 次和 5 次；100k 不预热并采样 1 次，只作为压力结果。
- 分配量来自当前线程的 `GC.GetAllocatedBytesForCurrentThread` 差值。
- 候选 Edge 数统计空间索引返回并去重的 Edge；全表扫描只统计覆盖、锚点和原生交点链中的几何枚举，不包含存档恢复、实体差异摘要或调用方主动遍历。
- 10k 场景 P95 必须不超过 16.67 ms；100k 不参与通过判定。

## 结论

- 10k 下短路、完整覆盖、最近边命中和单边删除满足单帧预算。
- 长路提交的空间查询半径覆盖几乎整个数据集，10k 候选达到 10,000，P95 为 18.911 ms。
- 原生曲线提交即使位于空白区域，也执行覆盖与交点两次全表扫描，10k P95 为 42.769 ms。
- 多交叉提交在每个交点后重复执行全表锚点扫描；10k 平均访问 4,110,600 个 Edge，P95 为 68.910 ms，是当前首要优化目标。
- `UniformGrid.QueryBounds` 按矩形穿越 bucket 返回去重引用；折线和原生几何的覆盖、交点、锚点与拆分候选统一由几何包围范围收集，权威几何仍负责最终判定。
- 优化后所有 10k 场景 P95 均低于 16.67 ms，覆盖、交点和锚点链的全表扫描及访问 Edge 数均为 0。
- 100k 压力结果完整保留且不参与完成判定；其中多交叉从 2,528.012 ms 降至 15.841 ms。
- `road-graph:3.1`～`3.3` 的性能、空间占据和查询局部化验收条件均已满足。

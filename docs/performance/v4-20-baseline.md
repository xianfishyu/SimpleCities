# V4 四档地图性能与历史资源基线

本报告对应 [V4-20 工单 #21](https://github.com/xianfishyu/SimpleCities/issues/21)，记录 2026-09-13、提交 `8a484cb` 的计数约定、可构造性审计和资源实测。下文“当前”均指该基线版本，其生产准入最多接受 256 条规范道路边，无法完成 10K 连续交互验收；200 米格长还存在低于 10K 的几何上限。下面的 240 边渲染夹具和至多 256 边历史实验不能外推为 10K 达标。后续 [#24 容量报告](v4-24-capacity.md) 已验证目标规模准入，不改写本报告的旧版本实测结果。

领域用语沿用 [CONTEXT](../../CONTEXT.md)，道路范围和编辑粒度遵循 [ADR 0001](../adr/0001-v4-square-eight-grid-scope.md) 与 [ADR 0002](../adr/0002-grid-span-editing-and-canonical-edges.md)。本报告不改变地图、规范化或当前实现容量规则。2026-09-13 用户确认规模验收调整为：25/50/100 米三档仍为 10K，200 米档为合法满铺的 9,680 边，144 FPS 和响应目标保持不变。200 米满铺时全部边为单原子直段，密集折线另设合法场景并如实报告较低边数。

## 计数与几何可构造性

10K 指同一活动快照的 **10,000 条规范道路边**，对应 `RoadSnapshot.EdgeCount`。100K 同理。道路格段是选择作用区间，可以在同一规范道路边中包含多个；结构节点、格心路口、链点、表现片段、顶点与索引另行统计。它们不作为补足道路边数量的替代计数。

地图两轴为 `[-4000,4000]` 米，格长为 c，每边主网格间隔数 n=8000/c。忽略实现容量限制后，规范道路边的精确几何上限为：

`Emax = 2n(n+1) + 4n² = 6n² + 2n`。

水平和垂直道路可细分为共 `2n(n+1)` 条主格原子边，两组对角道路可细分为每格四条格角至格心原子边，共 `4n²` 条。所有合法道路都沿这些原子边行进，每条规范道路边占用非空原子边集合。中心线禁止正长度重叠，使不同道路边不能重复消费同一原子边，因此以上总数是上界。铺满全部原子边时，主格点度至少为 3、格心度为 4，没有应合并的同类型二度节点，所以上界可达。

| 格长 | n | 主格点数 | 格心位置数 | 规范道路边上限 | 10K 几何可行 | 100K 几何可行 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 25 m | 320 | 103,041 | 102,400 | 615,040 | 是 | 是 |
| 50 m | 160 | 25,921 | 25,600 | 153,920 | 是 | 是 |
| 100 m | 80 | 6,561 | 6,400 | 38,560 | 是 | 否 |
| 200 m | 40 | 1,681 | 1,600 | 9,680 | 否 | 否 |

可行档位存在精确计数构造：40×40 完整米字格产生 9,680 边，在外侧分离行加入 320 条互不接触的单格道路得到 10K；n≥80 时有足够空位。128×128 完整米字格产生 98,560 边，外侧加入 1,440 条分离单格道路得到 100K；n≥160 时有足够空位。独立道路端点不相接，不依赖保留冗余二度节点凑数。这是几何存在性证明，尚不是当前生产可载入的数据集。

`RoadTopology` 当前限制 512 节点、256 边、2,048 链点；正常编辑的 `RoadMutationDraft` 和严格 `RoadCodec.Read` 都执行限制。Codec 另外限制 1 MiB 载荷和 JSON 深度 6。四档当前都受 256 边准入阻塞；未来容量提升还需要单独检验载荷大小、拓扑验证和表现成本。200 米档的 10K 不可构造属于几何约束，提升实现容量不能消除。

## 当前渲染夹具与测量口径

夹具实现为 [V4PerformanceProbe.cs](../../tests/godot/V4PerformanceProbe.cs)，通过公共建造规划逐笔构造，再执行严格 Codec 往返。它包含中心 6×6 完整米字格（228 边）、11 条独立 L 形折线以及一条跨 8 格的直路；初始总量为 **240 规范道路边、109 结构节点、491 链点**。密集区包含主格点八向路口和格心四向路口；折线与长直路覆盖规范道路边和选择格段计数的区别。四档使用同一格坐标布局，按各自格长转换为米，均位于地图内。初始历史为空，预留 16 边容量供操作。

[运行脚本](../../tests/godot/v4_performance_baseline.gd) 在真实渲染的 `frame_post_draw` 之间记录墙钟间隔；帧预算为 `1000/144 ≈ 6.9444 ms`，统计 P95、P99、最大值、超预算帧数及比例。关闭 VSync 和 FPS 上限，以实测结果中的渲染驱动、视口及引擎配置为准。两秒预热后分别采集十秒静止和十秒平移/悬停，再记录连续建造、撤销、八格类型改造及取消。计时样本只在采样结束后写出。

帧间隔用于判断连续渲染节奏，不等于单次领域操作耗时。操作报告分别保留工作队列等待、领域规划、纯表现准备、回到主线程的调度等待、主线程表现预检、核心引用提交、表现发布，以及输入到首次 frame_post_draw 的端到端时长。领域与表现准备、核心与表现发布另有合计；提交之间没有异步间隔，但以调用边界时间戳分别度量。100–300 ms 的交互目标需要实际输入处理到可见结果证据；核心计时不能替代这一边界。

### 渲染结果与复现

最终原始样本为 [render-25.json](../../.scratch/v4-20-qa/render-25.json)、[render-50.json](../../.scratch/v4-20-qa/render-50.json)、[render-100.json](../../.scratch/v4-20-qa/render-100.json)、[render-200.json](../../.scratch/v4-20-qa/render-200.json)。[summarize.py](../../.scratch/v4-20-qa/summarize.py) 从原始序列重新计算并核对分位数和超限数量，输出 [summary.json](../../.scratch/v4-20-qa/summary.json)。分位数采用排序后 `ceil(N×p)-1`，不剔除长尾样本。

从仓库根目录复现；以下渲染命令只启动一次进程，默认依次测量四档：

```powershell
dotnet build SimpleCities.csproj -c Debug

Remove-Item Env:V4_PERF_SMOKE -ErrorAction SilentlyContinue

```

本次为 Godot 4.7 stable Mono Debug，实际 Vulkan 1.4.351 / Forward+ / NVIDIA GeForce RTX 5080，1600×900 窗口和视口，VSync 关闭、`max_fps=0`、60 Hz 物理步进、低处理器占用模式关闭。四档在**同一进程按 25→50→100→200 米**顺序测量，JIT/运行时缓存状态不同，以下数字不能用作格长间性能排名。正式 Release 渲染尚未测量。

每档两秒预热、十秒静止、十秒平移/悬停，以及 30 次四格建造、30 次撤销、30 次八格拖选改造、10 次 Esc。静止和平移视野位于中心密集路口，操作视野移至长直路区域；操作阶段帧数按实际结束时间统计，没有用固定时间人为截短较慢操作。撤销从 `UndoRoadEdit` API 调用计时，建造和改造从提交输入处理计时，因此撤销不声明覆盖真实快捷键分发延迟。首次绘制检查 presented token 与当前状态一致。

后续复核确认，`panHover` 每帧注入中键相机 motion 和普通 motion，两者都会触发选择查询；当时采用类型改造模式且目标类型与道路同为 Street，因此同类型格段被跳过，最终没有可见悬停高亮。该窗口覆盖相机移动与查询成本，不代表持续绘制高亮的成本。#25 需分别测量相机、查询和可见高亮场景；周期性长尾仅提示进一步采集分配/GC证据，尚未证明根因。

当前 240 边样本所有操作均低于 100 ms，因此也全部满足样本最大值不超过 300 ms 的编辑响应判据；低于 100 ms 表示更快，不算失败。四档各场景帧 P95/P99 均低于 6.9444 ms，但仍有超预算帧，故“所有采样帧均不超预算”的严格门不通过，不能宣称整体 144 FPS 达标。目标规模尚受容量阻塞，此处不外推 10K/9,680 边结果。

主线程表现预检实测最大 **7.2624 ms**，已定位为一次能够独占超过整帧预算的同步成本；后台纯表现准备最大 **16.2981 ms**，核心/表现发布通常为微秒级。这些阶段证据指明优化检查方向，但没有证明所有帧长尾由这些调用造成。平移/悬停阶段最长 **32.361 ms**，该窗口没有提交操作，不能直接归罪于表现预检。当前没有 OS 调度、GC 或驱动导致这些长尾的具体因果证据，相关定位保留给独立后续工作。

四档真实 Esc 共 40/40 提交前取消成功，没有丢失提交竞态，最大输入到空闲观测为 **1.962 ms**，快照和历史保持不变。该样本仅覆盖当前夹具中的四格新建，不能代表满容量重操作、批量改造或加载取消；完整 UI 恢复 100 ms 可作为候选警戒线，尚未成为已确认预算。

本轮先复现并修复了 25 米偏移格心路口的 binary64 近重合角点：一个 ULP 的短凸包边在转换为 binary32 后退化，导致合法路网表现预检失败。修复仅在表现凸包前合并舍入误差级角点，保持道路几何和准入不变。四档及不同偏移/地图边缘测试检查转换后非退化、四端接来源和路口覆盖；最终四档渲染均功能通过。Core 322/322、Application 968/968 通过，Debug/ExportRelease 构建均零警告零错误；六个改动 C# 文件的 Roslyn 诊断及全方案分析器为空，运行脚本 LSP 为空。独立性能控制台不在 solution，故其 CodeLens/分析器覆盖受限；独立 Release 构建零警告零错误。编辑器内25米夹具真实建造及DAP验证通过，stderr为空；LSP客户端重复打开文件记录为工具问题，未宣称编辑器日志完全为空。ExportRelease 构建成功不等于 Release 运行性能通过。

## 历史资源实测

复现命令和完整测量定义见 [历史基线 README](../../tests/SimpleCities.RoadCore.Performance/README.md)，原始读数见 [history.json](../../.scratch/v4-20-qa/history.json)。环境为 .NET 10.0.0、Windows 10.0.19045、x64、32 逻辑处理器、非 Server GC，测量时关闭分层编译。硬件清单见 [hardware.json](../../.scratch/v4-20-qa/hardware.json)：Ryzen 9 9950X3D，系统可见内存 50,618,658,816 B；清单含 RTX 5080 及多个其他/虚拟显示设备，不能仅凭清单认定实际渲染设备。

四档每个场景预热一次，再各独立重复五次 64 笔有效历史。始终强持有同一个当前快照及索引，通过释放历史前后的托管存活堆差测量边际空间；每次读数前重复三轮全代 GC，前后读数极差均为 0。以下数值在四档各五次重复中相同。

| 64 笔操作场景 | 历史估算 B | 边际托管存活 B | 最大单笔估算 B |
| --- | ---: | ---: | ---: |
| 独立一格直路建造 | 31,744 | 38,840 | 496 |
| 连续 32 格直路中间一格反复改造 | 57,344 | 56,384 | 896 |
| 连续 32 格直路整段反复改造 | 28,672 | 29,800 | 448 |
| 64 条独立一格直路一起反复改造 | 1,060,864 | 774,208 | 16,576 |
| 256 条独立一格直路一起反复改造 | 4,206,592 | 3,042,880 | 65,728 |

32 格整段仍可规范化成一条道路边，因此其历史空间小于中间一格改造产生的局部切分。256 边批量场景的 32,768 个变更实体端点对应 16,640 个不同引用对象，其中 256 个仍属于当前快照。领域估算会重复计数共享实体，也可能漏计集合等开销；它既不是逐对象堆分析，也不是一致的实测上界。进程工作集仅作背景，不作为历史独占空间。

公共 `PlanBuild` 拒绝第 257 条分离道路，活动快照保持 256 边。历史工具只引用 Core，不依赖 Godot，其操作计时包含格段构造/查询、Plan 和 Commit，不包含输入、表现预检、上传或首次绘制。

## 取消与计划释放

在 256 条合法独立道路上批量改造，工作线程发出入口信号后约 0.1 ms 请求 token 取消。四档各十次样本全部抛出 `OperationCanceledException`，当前快照引用保持不变；从调用 Cancel 前到工作线程 finally 的延迟为 **0.0219–0.1935 ms**。入口信号不是规划器内部检查点，该结果也不是 Esc 到 UI 恢复时间；提前完成的竞态需要单独计数。

额外保留同一个活动 Network 并释放已准备但未提交的 256 格段计划，四档各五次得到 **206,008 B** 边际托管存活空间。`RoadPlan` 没有显式 Dispose，其域数据由 GC 回收。清理后的三轮全代 GC 用时每档上界依次为 13.82、13.5639、14.8282、15.7304 ms；历史实验全体范围为 7.8851–16.5960 ms。这是强制全进程 GC 的实验成本，不能作为计划自身释放耗时或取消延迟，也不要求生产主动全代 GC。

## 候选预算与结论边界

本次最大 64 笔历史约 2.90 MiB 边际堆、4.01 MiB 领域估算，最大单笔估算约 64.2 KiB。累计估算 **8 MiB**、单笔估算 **256 KiB** 可作为后续监测和压力实验候选阈值，分别留有约两倍和四倍已测余量。它们尚未成为生产拒绝门；当前直路样本未覆盖 2,048 链点折线及密集路口的最坏改动。未来扩容后需重新测量，再决定提交前拒绝等产品行为，不能静默丢弃有效编辑的历史。

纯核心 token 取消 **10 ms**、Godot Esc 到工具恢复 **100 ms** 均为候选警戒线，需要在目标规模重操作证据基础上确认。未提交计划要求引用不再被保留，自然 GC 回收时机不承诺固定毫秒。200 米规模已经确认为 9,680 边满铺，不再属于待确认参数。基线测量及未达标边界已经明确，后续分别由[#24 容量与数据集](https://github.com/xianfishyu/SimpleCities/issues/24)、[#25 帧长尾与达标复验](https://github.com/xianfishyu/SimpleCities/issues/25)、[#26 历史/取消预算确认及准入](https://github.com/xianfishyu/SimpleCities/issues/26)承接；其中预算与单笔超限行为尚待确认。本报告完成不解除正式切换的规模、性能及参数门。

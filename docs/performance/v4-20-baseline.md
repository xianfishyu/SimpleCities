# V4 四档地图性能与历史资源基线

本报告对应[工单 #21](https://github.com/xianfishyu/SimpleCities/issues/21)，记录2026-09-21在`2b942a9`检查点基础上重新采集的结果。当前生产准入仍是512节点、256条规范道路边、2048链点及1 MiB载荷；本轮GPU夹具为240边，目标规模尚未进入生产准入。历史完成评论中的性能成绩不作为本次证据。

## 计数、构造与验收口径

10K固定指同一活动`RoadSnapshot.EdgeCount`中的10,000条规范道路边。结构节点、格心路口、道路格段、链点和表现片段独立计数；连续32格直路可以只是一条规范道路边。地图两轴为±4000米，1世界单位为1米，格长为25/50/100/200米。

每轴主网格间隔数为`n=8000/cell`。横竖原子边共`2n(n+1)`，两组对角线在格心分开后共`4n²`，故规范道路边几何上限为`6n²+2n`。每条规范边至少占用一条原子边，禁止中心线正长度重叠使它们不能重复占用。满铺时边界角点度3、其他边界主格点度5、内部主格点度8、格心度4，均不发生二度合并，因此上界可达。

| 格长m | n | 主格点数 | 格心位置数 | 规范道路边上限 | 已确认目标 | 100K几何可行 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 25 | 320 | 103041 | 102400 | 615040 | 10000 | 是 |
| 50 | 160 | 25921 | 25600 | 153920 | 10000 | 是 |
| 100 | 80 | 6561 | 6400 | 38560 | 10000 | 否 |
| 200 | 40 | 1681 | 1600 | 9680 | 9680满铺 | 否 |

以下存在性构造使用左下角起算的`[0,n]`整数格坐标，换算世界坐标为`(格坐标−n/2)×cell`。前三档的精确10K可以由40×40满铺的9680边，另加分离区域320条互不接触单格道路构成。25/50米的100K可以由128×128满铺的98560边，另加1440条分离道路构成：格坐标`y=130..147`的18行，每行放80条`[0,1],[2,3],…,[158,159]`水平段，均在160格边界内。这是合法几何存在性证明；当前容量检查会拒绝，未执行100K压力加载。200米满铺消耗全部原子边，无法同时保留多段折线，需另列补充折线场景。

本轮GPU夹具经公开planner构造和严格codec往返：240规范边、109结构节点、491链点，其中228边为6×6米字密集路网，11边是各一个转折的L形，另有一条8格长直路；最多每边3链点，不代表高链点最坏情况。四档实际节点、边和链点相同。独立折线视野居中覆盖全部11条L链，路口与操作视野分别记录；缩放上限使四档可见范围有差别，因此不作格长间性能排名。另在纯核心历史测量中覆盖820链点折线。

帧门沿用指南的P95≤`1000/144=6.9444 ms`，同时公开P99、最大值和超限数量。没有另加“所有帧零超限”的合同，但明显长尾仍须独立处理。响应按输入处理到正确结果首次`frame_post_draw`统计，≤100ms为期望目标、≤300ms为上限；低于100ms不算失败。Undo/Redo从API处理入口计时，不含真实快捷键分发；鼠标建造/改造/删除从抬起处理计时，不包含OS输入队列，按住选择时间另记并保留其渲染帧。

## 环境与测量方法

环境：Ryzen 9 9950X3D、32逻辑处理器，Windows 10.0.19045，系统可见内存49,432,284 KiB，RTX 5080；.NET SDK 10.0.112、历史CLI运行时.NET 10.0.12，Godot 4.7 stable Mono。实际渲染设备以每档启动日志为准，硬件枚举中的虚拟显示器不代表被测GPU。

每档单独启动新进程，Forward+/Vulkan、1600×900，VSync关闭、`max_fps=0`、60Hz物理步进、Debug构建。5秒预热只覆盖渲染，首次规划/撤销的冷路径成本仍保留。每档静止、平移/悬停和独立折线视野各10秒；建造/历史及8格改造阶段各至少10秒且至少30次，8格删除与撤销固定30组，Esc固定10次。操作阶段按完成时间结束，不截断慢操作。

平移/悬停按墙钟最多60Hz发送，不因高FPS成倍增加事件；8格拖选逐格跨帧、按最多60Hz发送，并记录持握时长。每次真实`frame_post_draw`记录墙钟间隔、单调时间、窗口焦点与最小化状态；未聚焦数据保留并标注。引擎焦点标记不是独立OS前台PID审计，uncapped帧间隔也不证明显示器扫描出了同样多的帧，本轮不宣称正式Release/目标规模达标。

分段使用Stopwatch：输入处理准备、worker排队、领域规划、纯表现准备、恢复主线程等待、Godot资源预检、核心引用提交、表现引用发布、发布至首绘。最后一项包含发布后HUD/选择清理，不能全部叫GPU耗时。每笔同时保存来源、desired/presented token、失败字段和输入/结果的`Engine.GetFramesDrawn()`计数及差值；差值保留原始计数器语义，不人为加1。GD帧时间与C#计时没有共同绝对epoch，不能据此断定某个长尾帧的根因。各分项P95或最大值不能横向相加。

原始记录及复算脚本位于[本次证据目录](../../.scratch/v4-20-20260921/)。运行命令：

```powershell
dotnet build SimpleCities.sln --no-restore
& ./.scratch/v4-20-20260921/run-baseline.ps1
& ./.scratch/v4-20-20260921/summarize.ps1
```

历史CLI命令与测量定义见[README](../../tests/SimpleCities.RoadCore.Performance/README.md)。正式四档GPU测量串行执行，未与构建、历史CPU实验或其他Godot测试并行。

## 历史保留与取消资源

四档每场景预热一次，再重复5次64笔有效操作，共160组。强持有同一个当前快照与索引，释放历史前后测托管存活堆差，弱引用确认历史不再保留；所有采样的三次GC后读数极差为0。下表在四档各5次完全一致，实际观测不是普适堆上界。

| 64笔场景 | 累计领域估算B | 边际托管存活B | 最大单笔估算B |
| --- | ---: | ---: | ---: |
| 独立单格建造 | 31744 | 38840 | 496 |
| 32格直路的中间一格反复改造 | 57344 | 56384 | 896 |
| 32格直路整边改造 | 28672 | 29800 | 448 |
| 256条单格道路一起改造 | 4206592 | 3042880 | 65728 |
| 每笔删除4条道路，共256条 | 90112 | 123456 | 1408 |
| 密集路口216边/220格段一起改造 | 3559424 | 2574336 | 55616 |
| 820链点/838格段整折线改造 | 1703936 | 867432 | 26624 |
| 同一820链点折线的局部一格改造 | 1717248 | 881768 | 26832 |

密集方格夹具由11条横路与11条竖路构造，四个二度角点合并，实际117节点、216边、436链点。折线是一条820链点规范边，所有夹具均通过公开建造和codec，但未覆盖2048链点最坏情况。256边批改中，32768次实体端点出现对应16640个不同对象，256个仍属于当前快照。估算重复计算共享引用，同时可能漏计集合开销；简单建造/删除的实测还大于估算，因此不把估算称为实际内存上界。进程工作集仅作背景。

纯核心40次token取消全部成功、无提前完成，取消调用至worker finally为0.0213–0.0746ms；它不包含Godot输入/主循环/工具恢复。另20次未提交256格段Plan释放后的边际空间为205504B，弱引用全失效。强制全代GC的历史实验成本为8.3011–15.4748ms、Plan实验为8.5709–14.5431ms，不能记为取消或Plan自身释放延迟；生产代码没有强制GC。

当前最大64笔约2.90MiB边际堆、4.01MiB领域估算、单笔约64.2KiB。累计估算8MiB和单笔256KiB仍可作为目标规模复验的监测候选，约有2倍/4倍已测余量；纯核心取消10ms、Esc至UI恢复100ms为候选警戒线。全部候选尚待#26确认，不作为生产拒绝门或自然GC时限；累计裁剪与单笔超限行为也未默认为静默丢弃历史。

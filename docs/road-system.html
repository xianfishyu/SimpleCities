    道路系统与行为规范¶

    本页统一定义当前 V4 的产品行为、数据不变量、操作生命周期及验收边界，设计取舍随对应规则维护。术语见词汇表，逐类签名由道路类参考维护。已接受的设计决定不代表对应功能已经实现或通过运行验收。

    地图与几何¶

    项目 约束
    单位与范围 一个核心单位和一个 Godot 世界单位均为 1 米；8×8 km，中心原点，两轴 [-4000,4000]
    格长 创建时选择 25/50/100/200 米，默认 100；写入存档，创建后固定
    主格点 两轴坐标均为格长整数倍，可沿水平、垂直和两组对角线的八方向建设
    格心路口 两轴各偏半格；对角线交叉形成真实连接；关联格心的线段仅沿对角方向
    数值 核心 RoadPoint/RoadVector 使用 binary64，引擎边界显式转 binary32；保持米制，不进行百倍缩放
    容量 至多 32,768 节点、16,384 规范道路边、131,072 链点；道路编码至多 32 MiB

    吸附比较主格点与格心距离，等距优先主格点。拖动终点投影到合法八方向，并限制为该方向内、边界内最远合法格点；不把任意矩形裁剪交点当作道路端点。格心横竖请求须拒绝，不能暗中换方向或生成四分之一格点。核心独立验证输入，吸附不替代校验。

    两条对角道路跨过格心时建立同一个路口。中心线和合法建设位置限于地图内；路面宽度、端帽和路口表面可自然伸出，不产生界外节点，也不只裁剪拾取而保留另一套画面。

    数值验证覆盖有限性、坐标/长度、容差、查询预算和 float 转换误差；画面与表面命中使用相同转换几何。动态局部原点或新的容差策略需要误差证据。

    米字网格范围取舍¶

    已接受（原 ADR 0001）。原 V4 指南要求完整迁移六类原生几何，但当前产品需求是方格八方向道路建设，因此首版限定为米字网格直线及多笔相连形成的折线路网。自由角度道路、其他网格和曲线算法不进入本版实现及验收，避免为没有对应交互需求的能力承担算法与验证成本。

    原曲线设计保留为未来资料；这项取舍不保证未来增加曲线无需内部调整，重新引入时须重新审定数值、查询、存档和表现契约。完整排除范围见验证与范围，原讨论见历史指南 §3。

    编辑行为¶

    建造¶

    1. 主键按下在合法起点开始草稿，拖动只改变一条直线终点；主键释放提交整笔操作。
    2. 一笔可以跨多格；下一笔可从已有端点重新开始形成折线路网。成功后不自动续建；无正长度草稿时结束，不遗留下一次点击会话。
    3. UI 区域不启动地图建造。预览与最终提交使用同一受限草稿。
    4. 拟建中心线与现有道路有正长度共线重叠时，显示红色冲突区间、说明拒绝原因并拒绝整笔。同类型、不同类型、反向、部分和完全覆盖使用同一规则；不跳过重叠部分，也不隐式改造类型。
    5. 点交叉、端点相接和仅路面宽度交叠允许正常连接。拒绝不改变路网、ID watermark 或历史。

    选择、删除与类型改造¶

    悬停选出指针命中的道路格段，按主网格间隔并被真实路口截断。格心两侧半段可独立操作；十格长或带转弯的规范道路边仍可局部编辑。路口中央分支不明确时不新增选择。

    按下开始累积，拖动按实际轨迹选取、去重并持续高亮，释放后整组执行。快速移动不能只采每帧落点；经过路口不扩散到所有分支，跨 UI 区域的轨迹不连接成额外选择。悬停预选与已累积范围在视觉上区分。

    删除只移除选中区间；类型改造可在四类 profile 间双向进行。已是目标类型的部分静默跳过；混合选择中的有效变化仍是一笔。Select 模式松开保留选择，Esc 清除；切换工具或来源失效清理适用草稿和选择。重复选择当前工具不清草稿。

    整笔无变化时不切分、不交换快照、不递增版本、不消耗 ID、不发变更事件、不显示等待或“已是该类型”提示，也不增加历史。每次有效手势对应一次撤销。

    格段选择与规范道路边分离¶

    已接受（原 ADR 0002）。玩家需要按格段删除或改造道路，而规范道路边可能合并跨越多个格段，直接按 Edge 处理会扩大鼠标实际选中的范围。因此保留规范道路边的连续折线模型，以带来源版本的道路位置区间表达选择，按主网格间隔及路口截断，高亮、删除和类型改造共用该作用范围。

    规划器在私有目标状态中完成必要的切分、删除或类型改变及重新规范化，再一次提交整笔手势；不为每个可选格点永久保留结构节点。这增加了区间规划的要求，但避免了整 Edge 误操作和以交互粒度支配路网存储边界，独立撤销仍以一次有效手势为单位。结构约束见规范化与载荷合法性，原讨论见历史指南 §4.2和§6.1。

    规范化与载荷合法性¶

    NodeId、EdgeId、RoadProfileId 是不同的强类型身份。结构节点位于端点、真实交叉/连接或类型分界；规范道路边是结构节点之间最大连续折线链。折点和普通格点无需永久成为节点，删除/改造按需私有切分并重新规范化。

    • 同 profile、无真实分支或类型分界的非结构性二度节点合并；不同 profile 分界保留。合法自环和平行边不能因未来模拟而禁止；平行边仍须有不同几何路径，不允许重复覆盖。
    • 开放边满足 startNodeId < endNodeId，链点从起点排到终点且首末坐标匹配节点。Node、Edge 分别按 ID 严格递增序列化。
    • 当前闭环由多笔直线连接形成。孤立纯环收敛时，保留收敛前节点中最小 NodeId 作为 rooted seam；自环起终点为同一节点。
    • 固定 seam 后逐点比较正反两个内部链点序列，先 X 后 Y，选字典序较小方向；首末链点均为 seam 坐标。自环的 Start/End（A/B）端角色保持不同，不能按节点 ID 去重。
    • 加入真实分支后，旧 seam 若成为可合并的普通二度节点，应收敛到结构节点，不能因旧 ID 小而阻止合并。
    • reader 验证载荷中既定 seam 的端点、几何、方向和拓扑，不猜测已消失的建造历史，也不静默修补非法载荷。同一规范内容及身份确定性往返；不同建造顺序可能产生不同 ID，不承诺同一 JSON 字节。

    节点和边 ID 为正，watermark 大于已有身份；失败、取消和无变化不消耗新身份。profile 目录版本为 1，身份为 dirt/street/arterial/highway；未知类型或版本拒绝。具体磁盘字段与槽事务见存档手册。

    状态与提交¶

    RoadMapScene 协调同一时刻的一笔操作。核心 RoadNetwork 只在完整来源仍有效、取消未获准且资源准入通过时发布私有冻结目标。输入适配不直接改拓扑，核心不依赖提交后 observer 成功维持一致性。

    阶段 工作及可观察结果
    Preparing worker 根据不可变来源规划、构造变化和纯表现数据；主线程做来源与资源预检；提交前可取消
    Cancelling 已接受取消的晚到结果失去发布资格；仍保留操作所有权，直到 worker 与准备资源清理完成
    Committed 同步引用提交已改变核心；界面切为更新显示状态，不再承诺 Esc 取消；继续发布对应表现，Esc 不取消也不自动撤销
    Drawn / 失败终态 首次正确版本绘制后记录响应；失败按是否提交决定保留原状态或进入重试

    操作未结束时不排队接纳下一笔路网写入；Load 与编辑互斥。相机、光标和预览保持可响应，计算由命令触发，无需按 144 Hz 重算路网。

    RoadStateToken 包含 network instance、lineage、content revision 和 change sequence。有效提交递增发布序列；undo/redo 可回到旧内容版本，但序列和 ID watermark 不倒退。RoadLocation 绑定 token、Edge 和整条折线弧长归一化参数，旧位置/选择/plan 不能跨来源使用。

    空间索引是可重建派生数据，用有界片段粗筛，报告 bucket、candidate、精确测试和结果数量。超预算明确拒绝，不回退成无界全图扫描。只读快照不暴露可写集合；路口查询提供端接、稳定顺序和几何关系，不定义交通许可、信号或容量。

    表现与故障恢复¶

    RoadPresentation / RoadDisplay 在 worker 准备纯数据；主线程创建、预检和上传 Godot 资源。RoadMapView 一次接管完整 presented snapshot/token，表面、拾取、高亮和 HUD 统计随之换代。表面位置不能冒充核心中心线最近点。

    profile 标称宽度 显示宽度 RGB
    dirt 8 2 159/118/82
    street 12 3 112/136/150
    arterial 24 6 84/139/155
    highway 32 8 182/153/93

    DisplayWidthScale=0.25 是地图符号比例，不定义车道、占地、速度、费用或通行容量。背景主/次网格和点阵的缩放、显示层及 RoadConfig 展示格长不改变核心地图。

    提交前准备或预检失败时，保留原活动路网和表现。提交后显示失败时，保留已提交核心和可用完整画面，暂停道路编辑并提供明确错误与手动重试；相机和调试保存仍可用。重试只重建当前快照，不重复编辑、不增加历史、不并发启动第二次重试；设备失效时不能保证旧资源仍可画出。正常成功操作不得以失败重试作为惯常流程。

    历史与加载¶

    最近 64 笔有效编辑使用同一组领域变化支持 undo/redo，超出条数淘汰最旧记录；不保存逐笔完整地图或绘图资源。估算字节仅用于诊断，不是独占堆测量或编辑拒绝阈值。

    失败、取消、NoChange 和显示重试均不入历史。撤销后再有效编辑丢弃 redo 分支。有未完成草稿/选择、计算、加载准入或不可编辑表现时，历史入口拒绝不允许的操作，不借请求隐式提交草稿。

    成功 Load 创建新 lineage，清空历史，联合重置工具和表现、更新当前槽；预检前不改变任何活动状态。加载准入捕获的草稿/选择不能被工具取消意图改写。完整加载、关闭和磁盘失败协议见存档手册。

    性能目标¶

    指标 目标与计时边界
    渲染 144 FPS，整帧约 6.9444 ms；报告 P95/P99/最大值及超预算帧
    编辑响应 争取 100 ms、上限目标 300 ms；从释放输入到正确 token 的首次 frame_post_draw，包含规划、等待、预检、提交和发布；不是最少等待 100 ms，也不是显示器物理扫描时间
    超时提示 超过 300 ms 继续处理并显示等待；取消不必等到这个阈值
    取消警戒 token 到 worker 退出 10 ms，Esc 到工具恢复 100 ms；超时继续显示正在取消，不强停线程或伪报完成

    容量合法不等于持续性能达标。目标数据集包括 25/50/100 米各 10K 规范边、200 米 9,680 边及独立 320 边折线载荷；链点、格段和路口分别计数，100K 不作本版自动准入保证。硬件、典型手势、窗口、版本和残余长帧接受范围须关联具体报告。

    验证与范围¶

    验收从公开操作的可观察结果出发，覆盖边界方向、格心交叉、自环/平行边、重叠拒绝、格段轨迹、类型改造、无变化、64 笔历史、来源失效、加载、取消竞态、资源预检和提交后重试。对每类失败同时验证拓扑、身份、历史和可见表现；不为了测试暴露私有 WorkingState 或复制实现算法。

    几何用例包含中心与边缘、正反方向、相交/相接/共线覆盖、非法起点/方向和预算拒绝；序列化包含确定性往返、损坏字段、旧格式拒绝和活动状态保护。纯核心独立测试，应用避免重复编译，Godot 实测验证真实手势、正确首绘、资源和导出。V4 原切换须先隔离验收再切换正式装配，最后清理旧路径；记录仍在历史报告中。

    表现验收组合地图边缘、缩放与方向；对同一规范内容，正常编辑后的重建与 Load 路径必须生成一致的可观察 mesh、surface owner、命中位置及高亮范围。所有这些结果属于同一 presented 版本，实际改动须与逐段高亮对应。

## 重要决策

- 第二代目标是成熟的铺路系统和道路网络存档，不包含道路分级或交通模拟。
- 玩家玩法继续使用米字型八方向网格；`RoadGraph` 必须独立于网格并支持任意拓扑。输入规则通过可替换策略提供，三角形和六边形只用于验证可替换性。
- 权威几何必须保存真实曲线类型和控制参数，覆盖直线、Bézier、样条、圆弧/圆锥曲线及铁路缓和曲线，至少包括回旋线/clothoid；显示采样不能取代权威几何。
- 同一二维平面内的几何交叉一律形成拓扑连接。桥梁、隧道、立交和高程分层延期。
- 玩家交互包含连续多段铺路、拐点与预览调整、取消、连续拆除、框选删除、撤销与重做；玩家自由曲线编辑器不是第二代硬性要求。
- 存档采用多个玩家命名槽，支持另存为、覆盖确认、列表、加载、删除和独立自动存档。列表元数据包括存档名称、保存时间、城市名称、人口、资金和缩略图，缺少业务来源时允许明确占位。
- 第二代只保存 RoadGraph 业务状态；未来系统使用独立 JSON 扩展。旧存档不兼容，也不提供迁移。
- 10k Edge、60 FPS、P95 不超过 16.67 ms 是硬门槛；100k Edge 仅压力测试并记录结果，不阻塞完成。
- RoadType 数据、样式、选择和升级全部迁移至第三代；TrafficGraph、A*、拥堵和增量同步晚于第三代。
- 所有系统待办完成后必须执行完整自动化、构建、Godot 运行时、手工流程和性能评估，证据永久记录在附录 D。

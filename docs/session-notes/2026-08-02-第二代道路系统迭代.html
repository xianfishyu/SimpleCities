    2026-08-02 会话整理：第二代道路系统迭代¶

    作用域：SimpleCities 项目本地会话记录 存放位置：docs/session-notes/ Git 状态：本记录与所述实现、测试及规范文档在同一提交中跟踪

    会话目标¶

    阅读 docs/manuals/road-system-v2-gen.md，以后附录 D 的第二代最终范围为准，按各系统 docs/todo/ 的依赖顺序逐步实现、验证、记录并提交 RoadGraph、存档和工具输入工作。

    已完成¶

    • 完成 road-graph:0.6：强化正交/对角交叉、waypoint 拆分、单边删除和整组删除回归，显式校验节点邻接、Group 归属、空间命中和删除不创建替代 Edge。
    • 完成 road-graph:0.7：FindClosestNode 与 GetOrCreateNode 共用 FindClosestIndexedNode；节点身份半径固定为包含边界的 0.5f，多候选选择最近节点，近似等距时选择较小 Node ID。
    • 完成 road-graph:1.1：确认 RoadGroup 是自动合并的唯一硬边界；不同 Group 的独立玩家提交不会因共线而合并。
    • 完成 road-graph:1.3：使用统一距离平方 epsilon 排除近似共享端点，避免伪内部交叉拆除并重建既有 Edge，同时保留真实四连接交叉。
    • 完成 road-graph:2.2：删除未调用且依赖 DirectionUtil 的 RoadGraph.IsPathValid，使 RoadGraph 数据层不再引用方向枚举、输入网格或 CellSize。
    • 完成 road-graph:2.1：新增 SubmitPolyline、RoadPathSubmissionResult 和结构化错误枚举，在写图前拒绝非有限坐标、几何退化、节点身份塌缩、重复点和自交/折返；旧 AddRoad 复用同一链路。
    • 推进 road-graph:2.4 折线基础：公共结构化折线入口已建立；原生曲线写入与未知几何类型拒绝等待后续集成。
    • 推进 road-graph:2.4 提交契约：新增不可变 RoadPath 原生段请求快照；扩展提交结果为创建/删除 Node、Edge、Group 的确定排序摘要，现有折线交叉拆分和合并也返回完整实体差异。
    • 推进 road-graph:2.5（2026-08-03）：新增原生几何段统一参数域、查询和拆分契约，并完成直线段实现；曲线族、序列化及 GraphEdge 集成仍保持开放。
    • 推进 road-graph:2.5 cubic Bézier：原生保留四个控制点，完成解析位置/切线、精确极值包围盒、误差受控弧长和 De Casteljau 拆分。
    • 推进 road-graph:2.5 几何序列化：新增带显式版本和稳定类型判别的纯数据契约，完成直线与 cubic Bézier 的 JSON/DTO 往返，并在构造运行时对象前结构化拒绝畸形或不一致数据。
    • 推进 road-graph:2.5 GraphEdge 集成：GraphEdge 改以只读连续原生几何段作为长度和中间锚点的事实来源；现有折线写入、合并、拆分及旧 waypoint 恢复统一转换为 line 段，直接持有 cubic Bézier 时保留控制参数。
    • 推进 road-graph:2.5 样条：新增 cubic Hermite 原生几何段，保留端点与两端导数向量，完成查询、包围盒、长度、Hermite 类型拆分和版本化序列化。
    • 推进 road-graph:2.5 圆弧：新增以圆心、半径、起始角和有符号扫角表达的原生圆弧，完成解析长度、方向切线、轴向极值包围盒、同类型拆分和版本化序列化。
    • 推进 road-graph:2.5 回旋线：新增弧长参数化 clothoid，保存起点、起始航向、起终曲率和弧长，完成线性曲率、误差受控位置积分、保守包围盒、同类型拆分和版本化序列化。
    • 推进 road-graph:2.5 一般圆锥曲线：新增正权重 rational quadratic Bézier，保存三个控制点和三个齐次权重，完成有理位置/切线、解析极值包围盒、误差受控长度、齐次拆分和版本化序列化。
    • 完成 save-system:0.5：RoadGraph 恢复改为在临时 Node/Edge/Group 字典中全量校验，只有 schema、全局 ID、引用、成员关系、原生几何、端点和 nextID 全部有效时才一次提交；失败保持活动图和 ID 分配状态不变。
    • 完成 save-system:5.3：新道路 JSON 使用 schemaVersion、nodes、edges、groups 及对应 ID 字段，直接保存六类原生几何段的类型和控制参数，不迁移旧 Junction/Segment/Road payload。
    • 完成 save-system:0.3、0.4：新道路 schema 已移除 RoadType、旧类型回退和旧版本兼容；RoadGraph 与 manifest 均精确拒绝缺失、旧版、未来版和错误类型版本。
    • 推进 road-graph:2.4 原生提交：新增 SubmitPath(RoadPath)，六类原生几何和连续复合路径可从非 UI 调用方直接写入 GraphEdge；非法请求在任何写图前返回结构化错误，成功返回完整实体变更摘要并发出一致的 Edge 事件。
    • 原生路径端点解析支持近节点复用：line、cubic Bézier、cubic Hermite 和 rational quadratic 按类型重建端点/控制参数；circular arc 与 clothoid 只接受保持原生参数语义的整体平移，其他情况以 UnsupportedEndpointSnap 无副作用拒绝。
    • 推进 road-graph:2.6 最近点基础：RoadGeometrySegment 新增统一最近点结果与查询 API，line、circular arc 使用解析解，其余四类曲线使用原生包围盒和同类型拆分的分支限界搜索。
    • 完成 road-graph:1.2：FindClosestEdge 只由空间索引收集候选，最终逐 Edge 的全部原生几何段执行权威最近点查询；等距稳定选择较小 Edge ID，不再以端点、waypoint 或显示采样决定结果。
    • 推进 road-graph:3.2 原生几何空间占据：每个 RoadGeometrySegment 以保守 Bounds 覆盖全部 bucket，圆查询使用原生最近点过滤；恢复可重建、删除可完整清理曲线引用。
    • 推进 road-graph:2.6 点上判定：TryFindPointOnGeometry 在显式距离容差内返回权威参数、位置、距离和端点/内部分类，为后续按曲线参数拆分提供统一输入。
    • 推进 road-graph:2.6 直线交点：直线-直线使用解析参数并区分交叉、端点接触和重叠；直线与其余原生曲线使用包围盒剪枝和同类型细分，返回双方稳定参数及交叉/相切分类。
    • 推进 road-graph:2.6 曲线-曲线交点：统一 FindIntersections 对双方原生子曲线执行二维参数分支限界，覆盖单/多交点、内部相切、圆弧双交点、端点接触和无交点；完全相同且同参数方向的曲线直接报告 overlap。
    • 推进 road-graph:2.6 曲线重叠：新增双方参数区间结果，以第二参数升/降序表达同向/反向；通过端点权威参数对应和递归全区间验证识别五类非直线几何及直线的整段/部分重叠。
    • 推进 road-graph:2.6 多参数拆分：RoadGeometrySubdivision.SplitAtParameters 将无序、容差去重后的原几何参数逐次映射到剩余子曲线，返回保持原生类型的子段及各自全局参数范围。
    • 推进 road-graph:2.6 Edge 级原生拆分：新增内部 SplitEdgeAtGeometryParameters，把段索引和局部参数归一化为整条 Edge 的有序边界，一次替换原 Edge，并保持六类原生几何、端点 Node ID、Group、双向 EdgeRef、空间索引和 Edge 事件。
    • SplitEdgeAtPosition 改用各原生段的 TryFindPointOnGeometry 参数并复用 Edge 级拆分入口，旧折线提交的交叉和 waypoint 拆分不再把原生曲线降级为 line 段。
    • 推进 road-graph:2.4、2.6 原生离散交点提交：SubmitPath 在任何写图前查询新旧原生段交点，分别汇总既有 Edge 与新路径参数；每条既有 Edge 只替换一次，新路径直接以同类型子段建边。

    重要决策¶

    • 第二代范围以后附录 D 为权威；指南正文末尾的 Phase 2 分区系统不是当前 RoadGraph V2 的下一步。
    • SnapRadius = 0.5f 是连续空间数据层的节点身份容差，不与 CellSize 或 UI 网格吸附绑定。
    • GeometryEpsilon = 1e-4f 在位置比较中作为距离平方阈值；交点端点判定不再使用 Vector2 ==，且不与节点身份半径混用。
    • RoadGroup 表示一次用户提交，是第二代自动合并的唯一硬边界；RoadType 已从第二代运行时、API 和存档契约移除，第三代必须通过新契约和 schema 版本重新引入。
    • road-graph:2.2 只负责解除 RoadGraph 对方向和网格概念的依赖；折线路径的结构化校验由 2.1 完成，原生曲线提交与完整结果契约继续由 2.4 验收。
    • SubmitPolyline 是折线兼容入口，SubmitPath 是原生几何入口；两者共享最终 GraphEdge 写入方法。原生交叉、重叠和拆分事件已完成验收，road-graph:2.4 随本批关闭。
    • RoadGraphChangeSummary 以提交前后 Node、Edge、Group 权威 ID 集合差异生成，不尝试从事件顺序推断结果；因此交叉拆边、合并和实体替换都能稳定报告。
    • 原生几何段统一采用 [0, 1] 参数域；显示采样不进入 RoadGeometrySegment 权威契约，未来渲染采样只能作为派生数据。
    • cubic Bézier 弧长使用曲线弦长下界与控制多边形上界递归收敛，不依赖显示采样；包围盒使用导数内部极值而非控制点包围盒。
    • 原生几何序列化以 version = 1 和区分大小写的稳定字符串 line / cubicBezier 判别类型；当前版本拒绝未知字段和类型专属字段混用，后续格式演进必须提升版本并显式映射。
    • GraphEdge 的 GeometrySegments 是运行时权威几何；Points 暂作为现有渲染和折线拓扑算法的防御性兼容视图，仅表示段边界，不得成为曲线真相。
    • 本批不向旧 SegmentData schema 添加临时曲线字段；新 V2 Node/Edge/Group 命名、严格版本拒绝、完整校验和曲线参数存档由 save-system:0.4、0.5、5.3 一次完成。
    • 附录 D 未限定样条族；第二代采用 cubic Hermite 作为明确的原生样条语义，以端点导数表达连续性。其与 cubic Bézier 解析等价，但使用独立 cubicHermite 判别并在拆分后保留 Hermite 参数。
    • 单个原生圆弧的有符号扫角限制在一周以内；正负号保留逆时针/顺时针语义，较长复合路径由多个连续圆弧段表达。
    • clothoid 以弧长为权威长度，曲率在起终值之间线性变化；一般位置通过自适应 Simpson 积分获得，保守包围盒由路径弧长严格限定而非显示采样。空间索引阶段可收紧包围范围，但不得改变这些原生参数。
    • 一般圆锥曲线采用三个正权重的 rational quadratic Bézier 表达；三组齐次权重全部保留，使任意参数拆分后仍属于同一类型，而不是强制把子段端点权重归一化后丢失参数语义。
    • 新 RoadGraph 道路 schema 自身版本从 schemaVersion = 1 起步，字段名严格区分大小写；旧 version = 2 表示旧私有 payload，不继承为新 schema 的版本号，也不提供迁移。
    • RoadGraph 恢复以“完整临时状态 -> 一次提交”为事务边界；损坏 payload 通过 JsonException 返回诊断，失败时不清空图、不改变 _nextID、不发出 GraphCleared。
    • 第二代道路生产源码与存档 DTO 不保留任何 RoadType 兼容层；旧类型字段不会静默映射为默认道路分级。
    • RoadPath 的每个原生几何段当前形成一条 GraphEdge，相邻段共享 GraphNode；这保留控制参数并为后续按曲线参数拆分提供明确拓扑边界。
    • 原生路径覆盖判定不能复用把 Edge 端点连成折线的旧 IsPathCovered：line 只由现有 line 几何覆盖，曲线按版本化类型与参数精确比较，避免把曲线弦误判为已有道路。
    • 一般曲线最近点不采用固定显示采样：搜索队列以每个原生子曲线 Bounds 到查询点的距离作为严格下界，以当前最佳距离与最小未探索下界的差值作为停止条件；返回参数始终映射回原段 [0, 1]。
    • 空间索引保存的是可重建的 EdgeGeometryRef 候选服务：当前以每个原生段的保守包围盒覆盖 bucket，以权威最近点执行圆相交过滤；整段包围盒带来的候选放大留给 road-graph:3.1～3.3 测量和优化，不以显示采样换取较小候选集。
    • 点上判定将空间命中容差与端点参数分类容差分开：前者决定查询点是否属于几何，后者只决定命中应作为起点、内部还是终点处理；非法坐标和非有限/越界容差直接拒绝。
    • 直线-曲线交点不把固定采样作为权威：子曲线 Bounds 对直线的法向区间和切向投影区间提供剪枝，收敛叶节点映射回原曲线参数；相切点附近的连续容差命中按参数簇归并并保留残差最小候选。
    • 曲线-曲线离散交点使用双方子曲线包围盒的二维参数搜索，每步拆分空间范围较大的一侧；候选必须满足双方真实位置残差，并在双方参数维度组成连通簇，避免把同一相切根重复返回或把空间相近但参数独立的根混为一体。
    • RoadGeometryOverlap 的第一参数区间始终升序，第二参数保存与第一起止点对应的参数；第二参数降序即反向重叠。交换查询双方时必须同步重排对应端点，不能只交换四个数值字段。
    • 重叠候选来自双方端点的权威点上参数，不由离散命中数量推断；候选区间还必须递归验证位置残差、切线共线和方向一致性，避免两条多次相交但不共轨的曲线被误判为重叠。
    • 完全相同的版本化原生参数是封闭曲线同向重叠的无歧义快路径；整圆起终位置相同，不能仅依赖端点最近参数恢复完整同向区间，反向整圆仍由递归映射验证。
    • 多参数拆分始终以原几何全局参数排序，随后用 (parameter - previous) / (1 - previous) 映射到当前剩余子曲线；直接在每次拆分后继续使用原参数会产生错误边界。每个结果显式保留原参数范围，供 Edge 级拓扑映射使用。
    • Edge 级拆分参数使用 geometrySegmentIndex + segmentParameter 形成只用于排序的全局边界；相邻段的 (i, 1) 与 (i + 1, 0) 表示同一拓扑位置，只创建一个节点和一次切分。整条 Edge 的起终参数是无操作，不创建空 Edge。
    • 拆分替换保留原 Edge 两端 Node 实体；拆分节点只在几何精确位置容差内复用，避免旧 RemoveEdge 先清理孤立端点再分配新 Node ID。底层删除事务的全面整理仍留给阶段 4。
    • 原生提交交点采用“完整查询计划 -> 拆既有 Edge -> 创建新路径子 Edge”的顺序；交点查询阶段不修改图，Edge 拆分顺序按旧 Edge ID 固定，避免同一 Edge 因多个新路径段交点被重复替换。
    • 数值交点即使参数略离开端点容差，只要真实位置仍属于整条 Edge 的空间端点身份，就不得创建极短子 Edge；既有 Edge 和新路径都使用 GeometryEpsilon 空间过滤后再执行参数拆分。
    • RoadGeometryIntersectionResult.Intersections 与 Overlaps 分流处理：离散命中创建共享拓扑节点；连续重叠以双方区间边界拆分，并把新路径对应区间标记为已覆盖，不将连续集合伪装成离散节点。
    • overlap 计划同时保存旧 Edge 边界、新路径边界和新路径覆盖区间；新路径先细分再以原参数中点分类，因此重叠边界对齐后每个候选子段只可能是完整覆盖或完整未覆盖，不依赖序列化近似判断。
    • 当多个 overlap 区间并集覆盖整条新路径时，必须在拆分旧 Edge 前返回 FullyCovered；覆盖请求不得仅为补拓扑边界而改变既有图。
    • 图不变式使用内部 RoadGraph.AssertInvariants 作为单一诊断入口；空间一致性不再只以“查询能命中”为证据，而是核对登记引用集合、实体 ID、几何对象身份和每个引用的精确 bucket 覆盖。
    • 公共图遍历的“快照”在方法调用时立即固定成员，而不是首次枚举时延迟复制；实体引用本身通过只读包装、防御性复制和内部 setter 阻止外部绕过 RoadGraph 写入链。
    • DetachEdge 的职责止于移除 Edge 及其派生/反向引用；孤立 Node、空 Group、事件和不变式提交由顶层事务负责。该原语允许暂时不满足提交后不变式，不能作为公共删除 API。
    • 复合 Edge 变更不建立全局事件队列；顶层操作在最终图完成清理和 Debug 不变式验证后发布事件。所有移除事件先于所有新增事件，整组删除按 Edge ID 稳定排序，事件处理器始终查询到提交后的完整一致图。
    • 图几何端点不变式遵循 GeometryEpsilon 位置契约；圆弧和回旋线解析拆分产生的约 1e-6 合法残差不再由严格 Vector2 == 误报。
    • 存档管理交互由 PauseMenu 持有，GameHUD 只通过 ConfigureSaveManager 注入后端并继续协调暂停/场景切换；主菜单保存与读档不再隐式覆盖固定 autosave。
    • 覆盖、加载和删除共用确认视图并保存目标内部 ID；取消时返回存档管理视图。有效槽可执行三类操作，损坏槽只允许删除，避免把损坏 manifest 当作可覆盖或可加载目标。
    • 自动存档调度属于游戏场景生命周期，而不是全局 Autoload：只在 MapTest 活动期间计时，暂停场景树时不推进，离开游戏场景即停止。SaveAutosave 不改变 CurrentSlotID；只有玩家显式加载自动槽时才选择保留槽。
    • 自动/手动身份只由安全内部槽 ID 决定，不由玩家可见名称推断；因此手动槽可以合法命名为“自动存档”，仍显示为手动且不会被周期任务覆盖。
    • docs/reference/save-system-plan.md 是存档系统唯一详细当前参考；类参考、游戏逻辑和基础设施指南只保留各自层级摘要。未来 schema 或事务边界变化必须先以源码和自动化输出校准主参考，再同步这些导航入口。
    • IRoadInputStrategy 只负责指针吸附和路径草稿生成；RoadBuilder 负责生命周期，RoadGraph 负责权威校验与提交，三者不互相复制网格规则。
    • RoadPathDraft 防御性复制预览点并以可空 RoadPath 表达是否可提交；它是后续多段预览和其他网格策略共用的稳定边界。
    • 纯策略测试显式使用 64 单元验证逐格行为；Godot 运行时按 Scenes/road_config.tres 的实际 100 单元配置验收，文档和测试不得混用两套预期。
    • 三角形验证采用“单元中心跨边邻接”模型，因此每个锚点有 3 个邻居且相邻朝向交替；六边形验证采用 pointy-top 单元中心轴向坐标，每个锚点有 6 个等长邻居。它们不定义玩家 UI、背景渲染或寻路成本。
    • IRoadInputStrategy 保持窄接口；旧指南提出的 IGridGeometry 邻居枚举、成本和启发式属于未来寻路网格设计，不并入当前铺路契约。
    • 连续会话保存每次策略生成的完整 RoadPathDraft，组合时直接拼接原生 geometry segment；RoadBuilder 不根据网格类型或预览点重新构造权威路径。
    • 点击式连续会话与旧式拖拽并存：旧式拖拽释放直接确认单段；点击起点后左键固定拐点，Enter/双击确认，右键逐级回退或取消。最终拒绝不自动丢弃会话，以便继续调整。
    • 鼠标按钮和 motion 的 viewport 坐标通过 GetCanvasTransform().AffineInverse() 转换为世界坐标；铺路由输入事件更新，_Process 只保留拆除 hover 轮询。
    • 拆除选择与删除提交分离：连续模式按不大于半个 InteractionRadius 的步长补齐快速鼠标轨迹，矩形模式始终反映当前框而不累积离框目标；两种模式都只保存排序去重的 Edge ID，不缓存可失效的 GraphEdge 引用。
    • 简单点击是零长度连续轨迹并保持单 Edge 拆除；普通左键拖动选择连续路径，Shift+左键 选择与矩形相交的原生几何。松开左键才调用一次 RoadGraph.RemoveEdges，右键和工具/策略切换只取消预览。
    • RemoveEdges 对部分失效选择采用“删除仍存在目标”的确定语义；若全部目标无效则返回 false，任何成功批次都只执行一次清理和提交后事件发布。
    • 道路编辑历史选择完整 RoadGraph 状态而不是实体命令反演：这复用严格存档契约，确保交叉拆分、曲线参数、Group、ID 与 _nextID 一起恢复。代价是恢复后实体对象引用重建，且历史容量固定为 64；对外稳定语义是 ID 而不是对象身份。
    • 只有实际成功且改变图状态的铺路/拆路进入历史。新成功编辑清空重做栈；失败编辑保留当前有效重做分支，但若当前图已被外部修改，则在撤销、重做或下一次编辑尝试时清空旧历史，避免覆盖外部状态。
    • 曲线显示采用固定世界空间容差而不是随相机缩放重采样；默认 0.25 在当前最大 4x 缩放下约为 1 像素，同时保证相同图状态在加载和重建后生成完全稳定的点列。
    • 显示采样只属于渲染派生层：已提交道路、拆除高亮和有效建造预览共用它，但最近点、交点、拆分、空间索引、存档和编辑历史继续只读取权威原生几何。
    • 静态道路使用单个连续 ArrayMesh ribbon，而不是每 Edge 一个 Line2D 或每采样点圆形覆盖；共享左右边界从几何上消除段缝，节点标记独立使用一个 MultiMesh，因此渲染节点数不随 Edge 数增长。Edge 增删事件按事件循环合并重建，避免批量删除或交叉拆分重复构造全图；GraphCleared 仍同步完成一次全量重建。
    • 性能契约关闭专用 QA 进程的 VSync 和帧率上限，以 frame_post_draw 前后的实际提交耗时执行 16.67 ms 门槛；镜头、预览和高亮状态彼此隔离并在各自活动帧读取渲染计数，图恢复及批次重建作为独立一次性指标记录，不与连续帧 P95 混写。
    • 导出构建不得假设可执行文件所在目录可写；Godot 编辑器使用 res://saves，导出版本统一使用 user://saves。
    • 官方导出模板的 --script 路径覆盖在当前 Windows 模板中不可用；QA 导出改用 qa 自定义 feature 的主场景覆盖，避免正式运行时常驻测试 autoload 或修改正式主场景。
    • 本对话只维护本文件作为会话档案，不新增并行的会话记录。

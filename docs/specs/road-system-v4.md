# V4 米字网格道路系统规格

综合日期：2026-09-12。状态：规格及两层测试边界已确认并发布为 [GitHub #1](https://github.com/xianfishyu/SimpleCities/issues/1)，22张工作项已发布为 #2–#23。V4-01–06 与 V4-16 已完成，隔离场景支持开放端点续建和后台操作控制；其余条目仍是后续交付要求，不代表整套 V4 已实现或验证。

## Problem Statement

玩家需要在有限城市地图中准确地建造、删除和改造网格道路。当前道路选择主要以完整规范道路边为单位，一条跨越多格甚至转弯的连续道路可能被整条修改，难以满足“鼠标指向哪一格就处理哪一格”的操作预期；建造重叠缺少明确的预提交反馈，多种建造手势也增加了理解成本。

编辑过程中，玩家希望相机、光标和选择反馈保持流畅，耗时计算可以等待或取消，并且高亮范围、实际修改范围和画面所表达的路网保持一致。开发阶段还需要可靠的撤销和调试存档，以复现问题，而无需承担旧版本存档迁移。

现有道路核心还耦合了规划、状态、索引、表现协调及存档职责。原 V4 设计要求同时迁移多类曲线，超过当前米字网格玩法的实际需求。本规格将交付范围收敛到已经讨论确认的产品行为，并以可独立验证的道路核心和 Godot 适配层支撑这些行为。

## Solution

提供覆盖 8 km × 8 km 地图的米字网格道路系统，统一以米表达世界位置。玩家创建地图时选择格长，在主格点沿八方向建造，在格心路口沿对角方向继续建设；每次按下、拖动和松开完成一笔建造。

删除和道路类型改造均以道路格段为单位，路口截断选择。悬停显示预选范围，按住拖动累积选择并持续高亮，抬起后整笔生效。不同道路类型可双向互换，已经是目标类型的部分静默跳过。与已有道路发生共线区间重叠的建造统一标红并拒绝，正常交叉自动形成路口。

渲染以 144 FPS 为目标，道路计算和纯表现准备独立于渲染节奏；普通编辑从提交输入到正确结果绘制的目标延迟为 100–300 ms。超过目标继续等待，提交前允许 Esc 取消，提交后继续完成显示；独立撤销/重做保留最近 64 次有效编辑。显示准备和预检优先在提交前完成，异常时提供不重复修改路网的显示重试。调试存档只保证当前格式的可靠保存加载，不迁移旧格式。

## User Stories

1. 作为玩家，我希望地图覆盖 8 km × 8 km，以便在明确的城市范围内规划道路。
2. 作为玩家，我希望 1 个世界坐标单位表示 1 米，以便道路位置和距离具有一致的物理含义。
3. 作为玩家，我希望地图以中心为原点，以便在两轴各 -4000 至 4000 米的范围内定位道路。
4. 作为玩家，我希望创建地图时能选择 25、50、100、200 米格长，以便选择所需的规划密度。
5. 作为玩家，我希望格长默认 100 米且创建后固定，以便已有道路不会因网格设置变化被重新解释。
6. 作为玩家，我希望从主格点沿八个合法方向建造，以便遵循清晰的米字网格规则。
7. 作为玩家，我希望对角道路交叉时形成格心路口，以便道路在交叉处真实连通。
8. 作为玩家，我希望格心路口只允许沿对角方向起建，以便继续遵循原网格而不产生任意分数格点。
9. 作为玩家，我希望按下确定起点、拖动预览、松开建造，以便用单一明确的手势完成一笔操作。
10. 作为玩家，我希望一笔建造能沿同一方向跨越多格，以便快速建设长直路。
11. 作为玩家，我希望拖动只调整当前直线预览，以便鼠标轨迹不会意外形成多个折点。
12. 作为玩家，我希望通过从已有端点另起一笔来转弯，以便逐笔构造折线路网。
13. 作为玩家，我希望建造成功后结束本次手势，以便系统不会自动进入另一笔建设。
14. 作为玩家，我希望没有有效长度时松开鼠标不建路，以便普通点击不会留下退化道路或隐藏建造会话。
15. 作为玩家，我希望越界拖动停在当前方向上界内最远合法格点，以便预览与实际建设终点一致。
16. 作为玩家，我希望路面宽度、端帽和路口表面可以自然伸出边界，以便地图边缘不需要出现额外裁剪形状。
17. 作为玩家，我希望与已有道路重叠的建造区段标红并说明原因，以便提交前知道为何不能建设。
18. 作为玩家，我希望同类型和不同类型的共线重叠都拒绝整笔建造，以便不必记忆不同的覆盖规则。
19. 作为玩家，我希望部分重叠不会被悄悄跳过后只建设剩余部分，以便结果符合我看到的整笔预览。
20. 作为玩家，我希望普通交叉、端点连接和路口处路面交叠不被当作建造重叠，以便合法连接正常生效。
21. 作为玩家，我希望鼠标悬停时高亮将被操作的格段，以便点击前看清作用范围。
22. 作为玩家，我希望单击删除只作用于命中的格段，以便不误删同一条长道路的其他部分。
23. 作为玩家，我希望单击改造只作用于命中的格段，以便精确修改局部道路类型。
24. 作为玩家，我希望路口截断格段选择，以便点击路口一侧不会自动处理另一侧。
25. 作为玩家，我希望格心路口两侧的半段可以分别选择，以便独立删除或改造对角道路的局部。
26. 作为玩家，我希望按住拖动累积命中的格段，以便一次选择多处需要删除或改造的道路。
27. 作为玩家，我希望重复经过已选格段不会重复加入，以便拖动往返不会重复执行操作。
28. 作为玩家，我希望已经累积的选择在鼠标离开后仍保持高亮，以便始终看清本次操作范围。
29. 作为玩家，我希望悬停预选与已经选中的状态能够区分，以便理解哪些格段将随抬起生效。
30. 作为玩家，我希望路口中央无法辨认分支时不新增选择，以便避免误选。
31. 作为玩家，我希望鼠标移向具体分支后再选中该分支，以便准确控制路口附近的操作。
32. 作为玩家，我希望拖动经过路口不自动扩散到其他相连分支，以便只处理实际经过的道路。
33. 作为玩家，我希望快速拖动也不会遗漏轨迹经过的可选格段，以便选择结果不依赖偶然的渲染帧落点。
34. 作为玩家，我希望按住选择时只改变预览，抬起后才整笔执行，以便在确认前看清所有影响。
35. 作为玩家，我希望一次有效拖选对应一次撤销，以便整笔恢复误操作。
36. 作为玩家，我希望四种道路类型能够任意双向互换，以便既能升级也能改回其他类型。
37. 作为玩家，我希望改造时已经是目标类型的部分静默跳过，以便连续拖动不被无必要提示打断。
38. 作为玩家，我希望整笔没有实际变化时不产生等待或撤销记录，以便历史只包含真正发生的编辑。
39. 作为玩家，我希望道路计算期间相机、光标和预览继续响应，以便保持流畅操作。
40. 作为玩家，我希望画面以 144 FPS 为目标运行，而后台仅在需要时计算，以便编辑工作不会要求每帧重算路网。
41. 作为玩家，我希望普通编辑从松开提交到看到正确结果争取 100 ms、以 300 ms 为上限目标，以便得到及时反馈。
42. 作为玩家，我希望超过 300 ms 时继续处理并显示等待状态，以便稍慢的操作不会被自动终止。
43. 作为玩家，我希望提交前可以按 Esc 取消，以便放弃尚未生效的编辑。
44. 作为玩家，我希望“已取消”意味着路网确实没有改变，以便不用担心结果稍后突然生效。
45. 作为玩家，我希望提交后界面改为更新显示状态，不再承诺 Esc 取消，以便取消提示与实际状态一致。
46. 作为玩家，我希望 Esc 不会自动撤销已经提交的操作，以便取消和撤销具有明确区别。
47. 作为玩家，我希望同一时刻只处理一笔未完成编辑，以便操作顺序和作用对象清晰可控。
48. 作为玩家，我希望正常合法操作先完成必要预检，以便尽量避免道路已改变而显示失败。
49. 作为玩家，我希望显示失败时保留可用的完整画面并暂停道路编辑，以便不会用旧画面修改新路网。
50. 作为玩家，我希望显示失败后可以手动重试，以便在不重复建路或改路的情况下恢复显示。
51. 作为调试者，我希望异常状态下仍能移动相机并保存已提交路网，以便保留复现问题的数据。
52. 作为玩家，我希望撤销/重做保留最近 64 次有效编辑，以便恢复近期操作。
53. 作为玩家，我希望失败、取消、无变化和显示重试不增加历史记录，以便每次撤销都有明确含义。
54. 作为调试者，我希望当前格式的存档能确定性保存并重新加载，以便可靠复现同一份路网。
55. 作为调试者，我希望存档保存地图格长，以便加载时不受当前新地图默认值影响。
56. 作为调试者，我希望未知格式或非法路网明确加载失败且不污染当前场景，以便准确识别损坏或不兼容数据。
57. 作为调试者，我希望保存失败不会破坏已有槽位，以便保留可用的调试样本。
58. 作为玩家，我希望加载地图后清空旧撤销历史，以便旧操作不会作用于另一份路网。
59. 作为维护者，我希望道路核心能够脱离引擎验证，以便快速检查编辑、查询和存档的外部行为。
60. 作为维护者，我希望可见道路、高亮、点击定位和实际修改对应同一版本，以便避免视觉与领域状态混用。
61. 作为维护者，我希望性能报告区分帧时间、后台计算和编辑响应延迟，以便定位真正影响体验的瓶颈。
62. 作为维护者，我希望只在 V4 验证通过后切换正式装配，并移除旧生产道路路径，以便系统始终只有明确的权威路网与存档入口。

## Implementation Decisions

1. **交付范围。** 遵循已接受的 ADR 0001，本版仅实现米字网格线段及由多次编辑形成的折线路网。自由角度道路、其他网格及曲线实现不迁入，保留未来设计说明；未来扩展不承诺无需内部调整。
2. **工程边界。** 新建纯 .NET 的 SimpleCities.RoadCore，使用 net10.0；核心不引用 Godot、场景树、Resource、UI 或应用存档协调器。应用工程通过程序集引用使用核心，源码不得重复编译。Model、Geometry、Spatial、Queries、Mutations、Editing、Serialization、Presentation 是职责分区，不预先为每个小模块创建独立程序集或接口。
3. **世界与地图。** 1 核心单位与 1 Godot 世界单位均等于 1 米；地图中心为原点，两轴范围均为 -4000 至 4000 米。格长为创建时固定的 25、50、100、200 米之一，默认 100 米，并作为地图内容保存；不在运行中重解释已建路网。
4. **网格身份与几何。** 主格点与格心使用明确的离散网格身份，实体身份与位置身份分离。主格点允许八方向建设，格心仅沿对角网格线建设；不产生本版规则之外的四分之一格等位置。对角线长度按实际米制距离计算。
5. **数值表示。** 核心 RoadPoint/RoadVector 使用 binary64，引擎适配显式转换为 binary32，不进行百倍单位缩放。必须验证有限性、合法坐标、几何长度、容差、候选预算和转换误差；画面与表面拾取共用转换后的几何。首版不预先引入动态局部原点，是否需要由约定范围内的误差证据决定。
6. **路网模型。** NodeId、EdgeId、RoadProfileId 为不同的强类型身份。结构节点形成于端点、真实交叉/连接或类型分界；普通格点和折点不必永久保留为节点。规范道路边仍是结构节点之间的最大连续折线链，支持自环与不同路径的平行边；平行边不意味着允许几何重复覆盖。自环的两个端接必须可区分，闭环采用确定的起点与方向规范。
7. **编辑粒度。** 遵循 ADR 0002，道路格段是交互选择范围，独立于规范道路边。删除和改造请求携带来源版本及选中位置区间；规划器按需切分、删除或修改类型并重新规范化，不把整个 EdgeId 当作最小编辑目标。
8. **道路类型。** 内置目录版本为 1，包含 dirt、street、arterial、highway，允许任意双向互换。未知类型或目录版本明确拒绝；本版不提供运行时自定义类型。宽度、颜色等表现属性不代表车道数或通行容量。
9. **建造重叠。** 拟建中心线与已有中心线有正长度共线区间重叠时，不论类型、方向、部分或全部覆盖都整笔拒绝，返回冲突区间供红色预览。合法点交叉、仅端点连接和表面宽度交叠不按此规则拒绝。拒绝不得改变路网、身份分配或历史。
10. **单笔建造。** 鼠标主键按下确定起点，拖动得到一个合法方向上的直线草稿，松开整笔提交；成功后结束会话，不自动续建。未形成正长度合法草稿则不建路、不保留后续点击会话。越界预览约束到当前方向上界内最远合法格点；首版不迁入旧多次点击折线、Enter 或双击确认模式。
11. **选择与高亮。** 删除和改造按下选择、拖动累积并去重、抬起冻结选择。路口截断格段，格心两侧半段分别选择；中心歧义不新增选择，拖动不向其他分支扩散。悬停和累积选择的高亮须可区分并准确覆盖最终作用区间；轨迹选择不能只取逐帧落点。无效重叠的红色预览与可执行选择区分。
12. **无变化处理。** 已是目标类型的区间在改造中静默跳过；整笔无变化时不切分、不交换快照、不递增 token、不消耗 ID、不发布变更事件、不产生历史，也不显示“已是该类型”提示。混合选择中的实际变化作为一笔提交。
13. **唯一发布点。** RoadNetwork 将 Plan 与 Commit 分开。Plan 只根据不可变来源快照构造私有冻结目标、变更集及预算；RoadWorkingState 不暴露给消费者。应用装配可以基于该目标准备表现并预检，Commit 再校验来源 token、取消状态和已准备的准入结果，唯一地发布活动核心状态。核心不依赖提交后 observer 成功来维持历史一致性。
14. **身份与版本。** 有效节点和道路 ID 为正数；失败、取消和无变化不消耗 watermark。成功提交递增变更序列，undo/redo 可以恢复旧内容版本，但不倒退序列或 ID watermark；Load 创建新 lineage，新 network 使用不同实例身份。旧 plan、位置和选择不能跨来源身份复用。
15. **公开读取。** 所有消费者读取同语义的不可变快照，通过只读模型获取实体、端接、最近点、交叉和局部查询；不暴露可写集合或索引页。RoadLocation 绑定来源 token、道路身份和几何参数，切分或合并后不能继续按旧身份解释。表面命中位置不冒充核心中心线的精确最近点。
16. **空间与路口读取。** 空间索引是可重建的粗筛派生数据，使用有界片段，记录 bucket、candidate、精确几何检查和结果数量；预算超限明确返回拒绝，不静默全图扫描。JunctionReadModel 和 TurnMovement 仅描述端接、稳定排序及几何关系，不定义交通许可、信号或容量。
17. **调度。** RoadRuntime/RoadSystem 协调单笔操作，输入适配层仅把事件转换为会话和请求。道路规划及纯表现准备由命令触发，不要求以 144 Hz 运行；相机和渲染继续更新。待完成编辑不排队接纳下一笔路网写入，Load 与编辑通过操作状态互斥。
18. **表现准备。** RoadPresentationPreparer 提供纯数值道路表面、owner、位置及网格数据；普通编辑与 Load 共用准备流程。RoadRenderer 负责允许线程上的 Godot 资源生命周期、desired/presented token、预检和引用发布。核心提交前优先完成可失败的纯准备及资源预检，提交后不重新批量计算几何；延后调用本身不等于后台执行。
19. **取消。** 选择期间 Esc 清空本次选择；计算或预检阶段只要尚未提交就可取消，无需等到 300 ms。取消与最终同步提交由统一协调点确定先后，已接受取消的结果永久失去本次发布资格；清理未完成可显示正在取消。提交后 Esc 不取消或自动撤销，只继续完成显示，独立 undo/redo 保留。
20. **异常与重试。** 提交前预检失败不改变活动路网；提交后显示失败暂停道路编辑，保留可用的完整表现并提供手动重试，相机与调试保存保持可用。重试仅重建当前已提交快照的表现，不重新执行编辑或增加历史，不并发启动重复重试。正常输入不得把失败重试当作常规路径；设备已不可用时不能保证旧画面仍可绘制。
21. **历史。** 以一笔有效编辑为单位保留最近 64 次记录，达到条数上限淘汰最旧记录；undo 与 redo 使用同一组变更数据。只保存变化的领域内容，不存绘图资源或逐笔完整地图副本。历史仅在运行会话中保留，Load 后清空；字节预算及单笔超限策略尚待测量，不把旧 16 MiB 上限直接冻结为新门槛。
22. **存档。** 使用新的 simple-cities-v4 格式族和独立保存根。codec 是有界 stream 编解码器，保存规范实体、ID watermark、目录版本及地图格长等内容，不保存运行时 token 或样式资源；reader 拒绝未知/重复字段、非法类型、悬空引用、未建节点交点、非法网格、越界和错误闭环规范。当前版本要求确定性往返，旧格式可明确拒绝，不制作迁移器。
23. **加载协调。** RoadSaveParticipant 适配核心 codec；RoadLoadAssembly 与 SaveManager 协调 prepared 状态、场景代际和槽位发布。最终多参与者引用提交须满足无异常、无 yield、无文件或资源创建、无用户回调的前提；预检未通过不能开始发布。保存失败保留已有槽位，加载失败保留当前场景。
24. **边界表现。** 道路中心线与合法建设位置限定在地图内，路面宽度、端帽和路口表面可自然伸出，不引入边缘网格裁剪或界外结构节点。表现与拾取所依据的几何保持一致。
25. **切换。** V4 在独立核心测试及隔离场景验证期间，正式主场景继续使用唯一 V3 runtime；必要证据具备后一次切换正式装配，再进行复验与清理。最终只有一个生产路网、写入点、reader 和 writer，旧曲线代码及旧道路实现不作为常驻兼容运行路径保留。

## Testing Decisions

以下两层测试边界及其覆盖范围已经用户确认；此处定义验收方式，不声称已运行或通过任何测试。

1. **主要测试边界：公开道路操作及其可观察结果。** 在纯 .NET 中从 RoadNetwork 的 Plan/Commit、公开只读快照及其协作的编辑历史、codec 入口验证一笔操作的最终路网、查询结果、版本、历史和序列化行为。优先通过这些高层入口覆盖几何与索引协作，不为测试公开 WorkingState、builder、bucket 或内部集合。
2. **必要的引擎边界：真实输入到可见结果。** 使用隔离 V4 场景和最终主场景，从输入/工具命令入口观察格段高亮、鼠标分支选择、资源发布、点击位置、取消提示、重试与存档装配。该边界补充纯核心无法证明的 Godot 行为，不让渲染测试替代领域正确性，也不让 headless 构建替代可视验证。
3. **好测试的标准。** 给出合法初始路网、一次可理解的用户操作及可观察的预期；断言连接关系、实际变化范围、拒绝或无变化结果、历史条数、内容往返和版本一致性。避免断言私有方法调用次数、内部集合布局、无必要的对象引用相等或为迁就实现而复制算法。
4. **已有测试先例。** RoadGraphTransactionV3Tests 通过公开编辑与撤销入口检查版本和过期请求；RoadEditHistoryTests 提供历史行为先例；RoadUpgradeSessionTests 与 RoadRemovalSessionTests 提供拖动选择和表面来源的测试方式；现有 render-token、输入策略和加载代际 runtime contracts 提供真实场景观测方式；PreparedAggregateLoadTests 提供先交换全部参与者再通知的契约先例。沿用这些边界和方法，不照搬旧整 Edge 选择、部分重叠跳过、多次点击建造或曲线交付要求。
5. **核心代表性场景。** 四档格长、主格点/格心起建、直线延伸、点交叉、格心路口、端点连接、闭环、自环、不同路径平行边和折线交叉均得到明确结果。正反向、同异类型、部分全部共线覆盖均整笔拒绝；候选超限、非法数值和过期来源不改变活动路网。
6. **格段编辑代表性场景。** 长规范道路边的中间一格可独立删除或改造，未选区间保留；格心路口只选一侧；拖动跨越多格、重复经过、快速移动和经过歧义路口不扩大选择。四种类型双向互换，同目标区间及整笔无变化静默处理，一笔有效手势一次撤销。
7. **显示与输入代表性场景。** 实际高亮范围与最终改动逐段对应，悬停和累积选择区分；旧多次点击建造模式不会残留。检查地图边缘、缩放及方向组合，验证 mesh、表面 owner、命中位置属于同一 presented 版本，正常重建与 Load 对同一内容生成一致的可观察表现。
8. **取消和故障边界。** 通过现有故障探针方式或最窄的外部资源边界控制失败，验证选择取消、预提交取消、晚到结果、取消/提交先后、资源预检失败、发布失败及重试。检查活动路网是否改变、历史是否重复、编辑是否暂停以及调试保存是否可用；不为覆盖每个内部异常点而扩大为无界故障矩阵。
9. **历史与存档。** 验证最近 64 次有效操作的保留、最旧记录淘汰、无效操作不计数、undo/redo 的内容与版本行为、Load 清空历史。验证当前 schema 确定性往返、格长不被默认配置覆盖、非法输入和损坏存档不污染活动状态、槽位保存失败保护。历史字节成本的测量另行报告，不将估算值视为实际独占堆占用。
10. **性能边界。** 帧时间与输入到正确结果首次完成绘制的延迟分别测量。渲染目标为 144 FPS，整帧预算约 6.9444 ms，报告 P95、P99、最大值和超预算帧；编辑目标为 100–300 ms，后台计算、预检、引用发布、表现发布和端到端等待全部计入对应阶段。逐项记录来源和 presented 版本，不把最大帧率配置当作实测通过。
11. **性能数据集。** 后续冻结合法 10K 数据集的计数对象，分别覆盖密集路口和密集折线场景，按四档格长验证可构造性；100K 仅作可构造情况下的压力记录。典型手势规模、硬件、渲染设置、采样窗口、分位数与严格判定标准尚待验收设计，不在本规格中虚构。
12. **工程与切换检查。** 核心独立编译且不加载 Godot，应用不重复编译核心源码；按阶段执行适用的构建、编辑器资源检查、真实场景和导出验证。隔离 V4 的必要证据先于正式切换，正式装配和旧路径清理后复验。文档检查只证明规格结构和链接，不计作功能或性能验证。

## Out of Scope

- 自由角度道路、六边形/三角形网格、Bézier、圆弧及其他曲线的运行时实现或迁移；未来几何说明继续保留。
- 多次点击折线、Enter/双击提交和自动连续起点建造模式，以及未在本次讨论中确认的额外交互模式。
- 从格心横竖起建、任意分数格点建设、运行中修改格长、地图无限延伸和未经证据要求的动态局部原点。
- 交通流、车辆、拥堵、复杂寻路、信号灯、车道、桥隧、立交、高程道路、经济费用、解锁和道路等级机制。
- 运行时自定义道路类型，以及将显示宽度直接解释为容量或车道数。
- 跨版本存档兼容、离线 converter、普通 Load 自动迁移旧存档和持久化撤销历史。
- 提交后用 Esc 自动撤销、补偿恢复原路网或把停止显示任务当作取消成功。
- 没有性能证据支持就预先加入 renderer chunk，以及无关相机/UI/文件系统的全面重写。
- 在本次规格综合过程中创建实施切片、运行代码迁移、执行正式 QA、提交代码或切换生产装配；这些属于后续单独确认的阶段。

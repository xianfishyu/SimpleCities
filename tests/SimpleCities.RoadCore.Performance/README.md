# V4 历史与取消资源测量

这是只引用 `SimpleCities.RoadCore` 的独立 .NET 10 控制台，不进入游戏生产装配，也不修改 solution。所有夹具先通过公开 `PlanBuild`/`TryCommit` 构造，再经公开 codec 验证及重新加载；不使用反射、非法几何或放宽资源上限。

从仓库根目录复现：

```powershell
$env:DOTNET_TieredCompilation = '0'
dotnet run --project tests/SimpleCities.RoadCore.Performance -c Release -- .scratch/v4-20-20260921/history.json
```

只在基准进程内关闭分层编译，减少采样期间 JIT 生命周期造成的非历史回收。每个格长/场景预热一次，再独立测量五次；每次从无历史的种子快照开始，提交 64 笔有效编辑。种子构建、序列化和加载不计入编辑耗时。四档格长为 25、50、100、200 米，坐标均在 ±4000 米内。每个场景完成后保留 64 笔 Undo、零笔 Redo。

## 测量边界

- `EstimatedBytes`：公开 `RoadEditHistory` 的领域系数估算，未对跨条目的共享实体去重，也没有完整计入管理对象；不是稳定堆上界，更不是生产准入预算。
- `MarginalHistoryManagedBytes`：构造路网和计划的 `NoInlining` 栈帧返回后，只留下同一个当前 `Snapshot` 和待释放 `History`。分别在释放历史前后读取 `GC.GetTotalMemory(false)`；始终强持有同一个快照及其索引，因此共享实体不会误算为可释放历史。差值包含历史管理集合，是边际托管存活空间，不是总分配量或所有实体大小之和。
- 每次堆读数先做三轮阻塞压缩全代 GC，每轮等待终结器再做第二次 GC，记录读数极差。辅助统计集合、网络及计划已退出栈帧。测量间只记录整数时间戳，不创建存活 `Stopwatch` 对象；堆采样使用标量，不创建额外采样数组。每组保留一个弱引用，确认移除强引用后的历史/计划确实已被收集。
- `Sharing`：通过公开 ChangeSet 统计节点/边端点引用的出现次数、去重对象数及与当前快照相同的对象数；这些统计用集合在堆测量前释放。几何数组、元数据与管理集合不在对象计数内，但其托管空间包括在堆差中。
- `ProcessWorkingSetBytes` 只提供进程背景，包含 JIT、运行时、原生分配和保留的 GC 页；不得作为历史独占内存。
- `OperationMs` 包含该夹具的道路格段查询、Plan 和 Commit，不含 Godot 输入、表现准备、预检、上传或首次绘制；不能凭它验收 100–300 ms 或 144 FPS。

## 2026-09-21 结果

原始记录：`.scratch/v4-20-20260921/history.json`。采样于 10:29:52 UTC 完成，运行时为 .NET 10.0.12、Windows 10.0.19045、X64、32 逻辑处理器，工作站 GC，分层编译关闭。主性能报告另列本机硬件。以下数值在四档、各五次重复中完全一致；160 组历史和 20 组计划实验的堆采样前后极差均为 0，释放后的弱引用全部失效。

| 相互独立的一格直路建造 | 31,744 | 38,840 | 496 |
| 32 格直路中一格反复改造，交替切分/合并 | 57,344 | 56,384 | 896 |
| 连续 32 格整条规范道路边反复改造 | 28,672 | 29,800 | 448 |

| 密集路口的 216 条边、220 个格段一起改造 | 3,559,424 | 2,574,336 | 55,616 |
| 820 链点折线的 838 个格段一起改造 | 1,703,936 | 867,432 | 26,624 |

密集夹具由 11 条横路和 11 条竖路构造，四个角的度 2 节点被规范化移除，实际为 117 个结构节点、216 条规范道路边、436 个链点。折线夹具由 20 行交替方向的锯齿链组成，包含 800 条对角格段和 19 条两格连接段，共 820 链点；建造后是一条合法规范道路边。两种夹具均在四档地图上通过建造及 codec 验证，但它们不代表 2048 链点的最坏情况。

连续 32 个格段整边改造的历史小于中间单格切分改造。256 边批量改造的 32,768 次实体端点出现对应 16,640 个不同对象，其中 256 个仍属于当前快照。估算会重复计入共享对象，而简单建造、删除又表现为估算小于实测堆；因此不能用统一倍率把估算当作真实保留空间上界。

第 257 条独立一格直路被公开 `PlanBuild` 以“超过当前道路路网的资源上限”拒绝，活动快照保持不变。当前 512 节点、256 边、2048 链点限制尚未扩展，前三档 10K 边和 200 米档 9,680 边目标不能加载，100K 压力样本也不能加载。此次只测当前合法规模，不能外推为目标规模已通过。

## 取消和未提交计划释放

四档各对 256 格段改造预热一次、采样十次。工作线程发出入口信号约 0.1 ms 后，调用者执行 `CancellationTokenSource.Cancel()`；边界为调用 Cancel 前的时间戳至 worker 的 `finally` 时间戳。本次 40/40 抛出 `OperationCanceledException`，延迟 0.0213–0.0746 ms，活动快照全部保持同一引用。此入口不是规划器内部检查点，不能保证取消发生在同一阶段。原始记录保留 Outcome 和 CompletedBeforeSignal，以免把提前完成误报为取消成功；本次没有提前完成。

这不是 Esc 输入到界面恢复的时间，不包含任务调度、Godot 帧循环或预览清理。不能据此认定完整 UI 响应达标。

未提交计划另测：强持有同一个活动 Network（加载后历史为空），移除已准备的 256 格段改造 Plan 的唯一强引用，再测堆差。四档各五次均释放 205,504 B，弱引用均失效。公开 RoadPlan 没有 Dispose，自然 GC 没有固定毫秒承诺。历史测量中的强制 GC 成本为 8.3011–15.4748 ms，计划测量为 8.5709–14.5431 ms；它们是实验强制全进程回收的成本，不能叫作取消延迟或计划自身释放时间，也不应写入生产代码。

## 候选预算与验收限制

当前最大 64 笔历史约 2.90 MiB 边际堆、4.01 MiB 领域估算，最大单笔估算约 64.2 KiB。累计估算 8 MiB、单笔 256 KiB、纯核心 token 取消 10 ms 仍只是监测/压力实验候选，尚未经产品确认，不构成生产拒绝门，也不证明扩容后足够。累计超限裁剪、单笔超限拒绝或其他行为由 #26 在目标规模证据与确认后处理；不能默认提交编辑却静默丢掉该笔历史。

本工具 Release 构建通过，0 警告/错误，全部实验进程正常退出。它不依赖 Godot，因此不替代主任务的解决方案构建、编辑器、DAP 和真实渲染验证。它未加入 solution，solution 范围的 CodeLens 不自动覆盖此项目；本次会话也未暴露 Roslyn 诊断工具，独立语义诊断门应明确记为不可用。

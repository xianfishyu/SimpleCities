    道路核心数据集与测量工具¶

    服务于 GitHub #21（V4-20）、#24 和 #26。#21 保存 256 边原准入内的 240 边基线；#24 提供 10K/9,680 目标规模及独立折线补充数据；#26 复验历史条数策略、共享资源和取消边界。目标规模达标与长尾由 #25 跟踪。

    数据与边界¶

    • RoadBaselineFixtures 只经公开 PlanBuild / TryCommit 构造四档合法地图。mixed 为 240 条规范边、109 个节点、36 个格心、492 个链点、252 个网格跨段；polylines 为 20 条独立折线、820 个链点、800 个跨段。
    • RoadSnapshot.EdgeCount 是规范边计数；网格跨段、链点、路口和表现三角形分别报告。
    • 生成工具严格 codec 往返后输出载荷；Godot 工具经普通 SaveManager 槽位加载，结束时删除自己创建的临时槽。
    • 核心工具为独立 .NET 10 Release 可执行项目，不纳入 Godot 运行程序集。测试项目链接夹具源码，通过公开行为验证。

    运行（当前入口，2026-10-21）¶

    先停止属于本任务的旧采样进程；核心 CPU/GC 与 Godot/GPU 顺序运行，不并行构建或跑其它基准。以下工程、脚本、参数和输出规则仅静态核对，本轮未实跑。

    $runTag = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N')
$coreOutput = ".scratch/road-core-$runTag"
if (Test-Path -LiteralPath $coreOutput) { throw '必须使用新的输出目录' }
$env:DOTNET_TieredCompilation = '0'
dotnet build SimpleCities.sln
if ($LASTEXITCODE -ne 0) { throw '构建失败，停止测量' }
dotnet run --project tests/SimpleCities.RoadCore.Performance/SimpleCities.RoadCore.Performance.csproj -c Release -- $coreOutput
if ($LASTEXITCODE -ne 0) { throw '核心测量失败，保留证据' }
$godotExecutable = (Get-Command godot.exe -ErrorAction Stop).Source
foreach ($cell in @(25, 50, 100, 200)) {
    & $godotExecutable --path . --resolution 1600x900 --position 100,50 --script res://tests/godot/road_performance_baseline.gd -- "--output=res://$coreOutput" "--cell=$cell" --warmup=5 --seconds=10 --cycles=30
    if ($LASTEXITCODE -ne 0) { throw '图形测量失败，保留证据' }
}

    Godot 必须为 Mono 版；不在 PATH 时显式设置 $godotExecutable。同一轮的核心生成与 Godot 读取使用同一新目录，之后再复测须新建 runTag。这个 CLI 核心/GPU 组合不是正式 Release 或 editor/DAP 通过证明；正式采集见QA 手册。

    24 的已有目标数据不随普通检出展开。重放历史目标或运行历史策略前先恢复并检查错误：¶

    python Scripts/QA/scratch_archive.py extract --directory v4-24-20260930
if ($LASTEXITCODE -ne 0) { throw '历史数据未恢复，停止后续命令' }

    归档只恢复原始数据/证据，不恢复或认证当前导出二进制；详细包、Git 历史回退及成员限制见归档索引。

    测量定义¶

    • 核心工具：每个历史场景先预热一次，再报告三次 64 笔历史实验；混合路网覆盖单跨段改造、全 252 跨段改造、每笔三跨段删除，折线覆盖全 800 跨段改造。保持同一个当前 snapshot 强引用，只释放持有历史的 network，比较强制 GC 前后托管存活字节；弱引用必须确认历史已回收。差值保留符号，GC 和引用释放耗时单列，不伪装成生产清理耗时。
    • 核心取消：后台全路网改造进入后立即发 token；区分请求前已完成与真正观测到取消，不声称请求必然发生在算法深处。不提交候选，检查 snapshot/历史未变。另对四档各五次已准备但未提交的候选测量释放引用及 GC 回收；保留原 network，弱引用确认候选已回收。
    • GPU 工具：每档独立真实 Vulkan 进程，禁 VSync、无 FPS 上限，混合与折线各预热 5 秒；静止、平移、可见高亮、平移加高亮、折线静止/平移各 10 秒，输入 60Hz。
    • 编辑窗口：30 轮真实鼠标建造四跨段、拖选三跨段改造/删除及 Ctrl-Z/Y；每轮恢复初始拓扑。另采 20 次 Ctrl-Z 后 Esc 的取消。编辑与取消窗口按操作次数结束，其实际秒数记录在 JSON。
    • 帧时间：相邻 frame_post_draw 墙钟差，保留逐帧数据、绝对起点与相对微秒时间；最近秩 P95/P99/max 与超过 1000/144ms 的帧数。引擎焦点计数单列；这不等同于导出包的原生前台 PID 门禁。
    • 响应：既有操作控制器的输入处理开始到正确 token 首次绘制；额外记录输入注入到测试观察完成，用于区分测试协程调度成本。GetOperationMetrics() 在每次操作完成后读取，不在逐帧回调分配字典。阶段未观测时为 -1，不补零。
    • Esc：分别记录请求到 worker finally、请求到工具清理可用；已提交竞态另列。不会在生产中强制 GC，也不自动应用候选历史字节预算。

    分析原始 JSON 时必须区分夹具规模、引擎 Debug / 核心 Release 和导出 Release；本工具的容量通过不代表端到端目标性能或正式场景通过；已有正式切换结果见带日期报告，不能当作本轮实测。

    #24 目标规模与容量正确性¶

    $env:DOTNET_TieredCompilation = '0'
$capacityOutput = ".scratch/road-capacity-$runTag"
if (Test-Path -LiteralPath $capacityOutput) { throw '输出目录已存在' }
dotnet run --project tests/SimpleCities.RoadCore.Performance/SimpleCities.RoadCore.Performance.csproj -c Release -- --capacity $capacityOutput
if ($LASTEXITCODE -ne 0) { throw '容量数据生成失败，停止后续操作' }
dotnet build SimpleCities.sln
& $godotExecutable --path . --resolution 1600x900 --position 100,50 --script res://tests/godot/road_capacity_runtime_contract.gd -- "--output=res://$capacityOutput"

    --capacity 经正常 PlanBuild/TryCommit 顺序构造四档和 polylines-200，输出严格 Codec 字节往返后的载荷、SHA-256、分离统计、阶段耗时、累计分配和 OS 进程生命周期峰值。后者跨数据集累计，不是单数据集独占内存；阶段末存活堆不是托管峰值。

    容量运行契约重用 v4_capacity_scenario.gd，可由 CLI 或编辑器运行场景中的临时 Node 执行，覆盖实际输入与正常保存重载。它不采持续帧率，不批准预算，不替代 #25。固定构造、320 条短折线的占比和限制见 容量报告。

    #26 历史策略及生命周期审计¶

    $env:DOTNET_TieredCompilation = '0'
$historyOutput = ".scratch/road-history-$runTag"
dotnet run --project tests/SimpleCities.RoadCore.Performance/SimpleCities.RoadCore.Performance.csproj -c Release -- --history-policy .scratch/v4-24-20260930/datasets $historyOutput

    输出目录必须不存在。此入口仅允许 Release 诊断进程；每个已验证的目标数据集覆盖局部改造、128 格批量改造、每笔删除 3 格和全图改造。在有合法剩余空间的场景另做 64 笔实际建造；200 米满铺不以非法建造凑数。

    补充夹具包括严格 Codec 验证的 10,272 点单条非自交折线，以及经公开建造规划器生成的 16,384 边上限路网。上限路网的全图类型改造用来验证用户已确认的“不因历史字节大小拒绝编辑”：单笔估算超过 4 MiB、64 笔累计估算超过 256 MiB 时仍保留全部有效编辑；这两个数字只是已弃用候选的回归反例，不是生产门。

    每个历史场景预热一次，再测三轮；记录 before/after 引用槽、按对象身份去重的实体数、与当前快照共享的实体数。计数集合在测量前释放；保持同一当前快照，释放 network/history，报告有符号的边际托管存活空间、引用释放及独立 GC 耗时，并通过弱引用确认历史回收。每套夹具另实际提交 65 笔，撤销及重做各 64 笔，检查只淘汰最旧记录。

    每套夹具做 40 次全图改造取消尝试：通过诊断输入枚举器观察 selection 已完成复制，再延迟 0/1/5/15 ms 发 token，各 10 次。报告实际延迟、worker 线程终于退出的时间、取消是否被观察、提前完成或晚到完成竞态，以及 10 ms 警戒线。该观测点不代表某个精确的内部拓扑阶段；不把主线程等到 Task 的时间冒充 worker 退出时间。

    另各准备并释放 10 个未提交计划，保持源网络存活，用弱引用分别确认 plan、目标 snapshot 和 change set 可回收且活动状态不变。强制 GC 仅用于独立诊断，清楚区分引用释放、回收以及 UI 恢复；本工具不证明 Godot Esc、GPU 帧率或正式切换通过。审计保存逐场景进度，失败报告保留，不覆盖旧证据。
